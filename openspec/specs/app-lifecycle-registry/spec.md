# app-lifecycle-registry Specification

## Purpose

应用生命周期注册表是应用启动与关闭顺序的唯一挂载底座：启动前、启动后、关闭前三类阶段登记表决定各处理类的执行次序，静态初始化承载类级启动副作用，单元注册表把各业务单元挂到接口视图下供检索装配。这一底座一旦单例性、顺序性或原子性失守，启动时序即不可信，并会留下"半注册""假最高级"这类在运行期才暴露的脏状态。本能力钉死阶段登记的幂等与并发首注册唯一、链式追加的方向约束、优先级数域边界、静态初始化的执行完备与异常透传、以及单元注册"全有或全无"的行为契约。

## Requirements

### Requirement: 阶段登记单例与并发首注册唯一
启动前、启动后、关闭前三类阶段登记表 MUST 遵循同一登记契约：同一处理类在同类阶段重复登记 MUST 恒返回同一登记实例（首次登记后再登记时，优先级参数被忽略——现契约）；多线程并发对同一处理类首注册 MUST 仅产生一个实例，MUST NOT 丢失注册、MUST NOT 报"已经存在"、MUST NOT 产生多实例。（旧实现内层表非并发安全，上述三种病症在竞态下均可能出现——本条为收窄旧行为的修复性契约。）

#### Scenario: 重复登记返回同一实例且保留首优先级
- **WHEN** 同一处理类在启动后阶段被登记两次，第二次携带不同的优先级参数
- **THEN** 两次返回同一个登记实例，其执行次序按首次登记提交的优先级确定

#### Scenario: 并发首注册仅产生一个实例
- **WHEN** 多个线程同时对同一处理类执行首注册
- **THEN** 所有线程拿到同一登记实例，无异常抛出、无注册丢失、无第二实例出现

### Requirement: 链式追加方向与链接位排他
阶段登记可沿链向后追加：后继节点的序号 MUST 不大于前驱节点的序号，追加更大序号 MUST 抛异常；前驱的后向链接位已被占用、或被追加节点已挂有前向链接时，追加 MUST 抛异常且 MUST NOT 覆盖既有链接；链接位空闲且方向合法的追加（含空链首追加）MUST 成功并返回被追加的后继节点。

#### Scenario: 方向合法的空闲位追加成功
- **WHEN** 向后继序号不大于前驱、且双方链接位均空闲的节点执行追加
- **THEN** 追加成功返回后继节点，前后驱关系可双向追溯

#### Scenario: 序号方向违规被拒绝
- **WHEN** 追加的后继节点序号大于前驱节点序号
- **THEN** 抛出异常，前驱与后继的链接均未被修改

#### Scenario: 链接位占用被拒绝
- **WHEN** 前驱的后向链接位已有后继，或待追加节点已作为他人后继挂有前向链接
- **THEN** 追加抛出异常，原有链接关系保持不变

### Requirement: 优先级数域边界显式拒绝
优先级序号的合法数域为闭区间，下界为最低档（序号 1），上界为最大整数值。请求高于上界 MUST 显式拒绝抛异常，MUST NOT 因整数回绕产出实际执行最晚的"假最高档"；请求低于下界 MUST 显式拒绝抛异常，MUST NOT 产出数域之外的 0 级档位；升降档的步数参数 MUST 为正数否则拒绝。以等于既有预定义档位的序号请求优先级时 MUST 复用该档位实例本身（同一身份）。（旧实现溢出回绕与 0 级放行——本条为收窄旧行为的修复性契约。）

#### Scenario: 越上界提升被拒绝
- **WHEN** 对已处最高档的优先级请求再提升（单步或多步）
- **THEN** 抛出参数异常，不返回任何回绕后的档位

#### Scenario: 越下界降低被拒绝
- **WHEN** 对最低档（序号 1）请求再降低
- **THEN** 抛出参数异常，不产出 0 级等非法档位

#### Scenario: 预定义档位身份复用
- **WHEN** 以与某预定义档位相同的序号请求优先级
- **THEN** 返回该预定义档位实例本身，而非等值的新对象

### Requirement: 静态初始化全部执行与确定序
声明了多个静态初始化方法的类在执行初始化时 MUST 全部执行其初始化方法，执行顺序 MUST 以方法名的字典序确定（同一输入不随运行随机变化）；其中任一初始化方法抛出业务异常时 MUST 以该异常原类型上抛给调用方（不得以反射包装异常遮蔽真实原因），且同类后续初始化方法自失败点停止执行；同一类以同一声明集构建的初始化记录 MUST 相互等价（相等且排序一致），合并入全局集合时 MUST NOT 被静默去重丢失或重复计数。（旧实现同类多方法仅随机执行其一且失败静默——本条为收窄旧行为的修复性契约。）

#### Scenario: 多初始化方法全部按名序执行
- **WHEN** 一个声明了两个初始化方法（方法名字典序与其声明书写顺序相反）的类被执行初始化
- **THEN** 两个方法均被执行恰好一次，执行顺序为方法名字典序

#### Scenario: 业务异常原类型上抛
- **WHEN** 某类的初始化方法抛出输入输出类业务异常
- **THEN** 调用方直接捕获到该业务异常本体（含原始信息），而非反射包装异常

#### Scenario: 同源初始化记录等价不丢失
- **WHEN** 同一类先后构建两条初始化记录并全部加入全局待执行集合
- **THEN** 两条记录判定相等、排序一致，集合中恰有一份生效，其余类的记录不受牵连去重

### Requirement: 缺失初始化声明分别显式失败
为一目标类构建初始化记录时：目标缺少生命周期声明注解 MUST 显式失败并报出自身原因；目标带有声明但无任何可执行的静态初始化方法 MUST 以"初始化方法缺失"类异常显式失败。两类失败 MUST 可区分，且 MUST NOT 静默构建一个什么都不执行的可用记录。

#### Scenario: 声明齐备构建成功
- **WHEN** 为带生命周期声明且至少含一个静态初始化方法的目标构建初始化记录
- **THEN** 构建成功，执行时其全部声明的初始化方法生效

#### Scenario: 缺生命周期声明显式失败
- **WHEN** 为没有生命周期声明注解的目标构建初始化记录
- **THEN** 构建即时失败并抛出指明缺失声明的异常

#### Scenario: 缺初始化方法显式失败
- **WHEN** 为带声明但不含任何静态初始化方法的目标构建初始化记录
- **THEN** 构建失败并抛出区别于缺失声明场景的"初始化方法缺失"异常

### Requirement: 单元注册三类名字全视图可查
带单元声明的对象注册成功后，其登记名字集合 MUST 包含声明值名（值名为空白时除外）、类型简名与类型全名，且这些名字 MUST 在该对象对应的每一个接口视图（标记接口继承链及声明视图）下全部可查并返回同一实例；与其无关的接口视图 MUST NOT 包含该对象。

#### Scenario: 注册成功后各视图三类名全可查
- **WHEN** 一个实现了两个标记接口、带非空白值名的单元注册成功
- **THEN** 两个对应接口视图下分别以值名、简名、全名查询均命中同一实例，登记返回恰含三个名字

#### Scenario: 无关视图不包含该单元
- **WHEN** 以该单元未实现且未声明的接口视图查询其名字
- **THEN** 该视图查询结果为缺失，视图内容不含该单元

### Requirement: 单元注册冲突整次零写入
单元注册 MUST 在写入任何名字之前完成整体预校验；只要其任一登记名字与既有注册冲突（或该对象无任何有效登记视图），整次注册 MUST 以异常显式失败且零写入——其任何名字均不可查、既有注册结果不受任何影响、后续重试 MUST NOT 遭遇半注册派生状态。（旧实现边写边校验，中途失败残留部分名字且重试必炸——本条为收窄旧行为的修复性契约。）

#### Scenario: 同名冲突整次拒绝不留部分注册
- **WHEN** 第二个单元与已注册单元简名相同（全名不同），对其执行注册
- **THEN** 注册抛出冲突异常，且第二个单元的值名与全名在其对应视图下均不可查

#### Scenario: 冲突失败后既有注册与重试均正常
- **WHEN** 冲突注册失败后，以既有注册的名字查询，或再次尝试同一冲突注册
- **THEN** 既有单元按三类名字仍命中原实例；再次尝试同样显式失败且仍无任何新增写入

#### Scenario: 无有效视图的对象零写入失败
- **WHEN** 注册一个接口继承链不含任何标记接口、也未声明登记视图的对象
- **THEN** 注册抛出异常，未向任何视图写入其名字

### Requirement: 声明未实现接口注册失败零写入
单元声明了自身并未实现（也非继承实现）的接口作为登记视图时，注册 MUST 在写入前以类型校验异常失败——该失败类型与名字冲突异常可区分——且其任何名字 MUST NOT 被写入任何视图。

#### Scenario: 谎报视图被拒绝且不落账
- **WHEN** 注册一个声明了未实现接口的单元
- **THEN** 注册抛出类型校验异常，其值名在声明视图及其它任何视图下均不可查

#### Scenario: 如实声明的注册正常生效
- **WHEN** 注册一个仅声明自己确实实现之接口的单元
- **THEN** 注册成功，该单元在每个声明视图下按名字可查

### Requirement: 查询缺省与严格失败语义
单元视图的名字查询 MUST 区分两种语义：带缺省值的宽松查询在名字缺失时 MUST 返回所给缺省值而非异常；严格查询在名字缺失时 MUST 显式异常。视图内无任何已注册单元时，对该视图的严格"取任一单元"查询 MUST 显式异常并报出视图为空原因，MUST NOT 返回空引用。

#### Scenario: 宽松查询缺名返回缺省
- **WHEN** 在某视图以未注册的名字执行带缺省值的查询
- **THEN** 返回缺省值本身，不抛异常

#### Scenario: 严格查询缺名显式异常
- **WHEN** 在某视图以该视图不存在的具体名字执行严格查询
- **THEN** 抛出指明该名字缺失的异常

#### Scenario: 空视图严格查询显式异常
- **WHEN** 对尚无任何注册单元的接口视图执行"取任一单元"的严格查询
- **THEN** 抛出指明视图为空的异常，而非返回空引用
