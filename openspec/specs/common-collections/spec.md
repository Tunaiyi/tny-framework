# common-collections Specification

## Purpose

本能力为全框架最底层的集合与键空间底座（事件通知器、服务发现监听、上下文属性容器等生产路径直接依赖）钉死外部可观察行为契约：惰性空集合在并发首写时不丢数据、读操作不改变可观测状态；属性键在同一 (命名空间, 名称) 下保持恒等实例且跨命名空间互不命中；集合收集、空迭代序列、散列锁槽与完成结果映射的语义与平台标准契约对齐、成功/失败方向不反转。审查确认这批底座存在"静默失效"型缺陷（并发首写互相覆盖、命名空间劫持、重复键误抛、耗尽返回 null、移除误写为追加、映射条件写反），本差量将修复后的行为正式入册。

## Requirements

### Requirement: 惰性空集合读取不改变可观测状态
系统提供的三种同族惰性空容器（列表、集合、映射）在空状态下 MUST 支持全部读取查询（尺寸、判空、包含判断、遍历）且不触发底层实体化；读取后 MUST 不改变实例的可观测状态——后续写入仍从空状态正常开始并累积。

#### Scenario: 空状态读取不物化
- **WHEN** 对新建的惰性空列表/空集合/空映射实例依次执行尺寸、判空、包含查询
- **THEN** 分别返回 0、真、假；实例仍处惰性空态，此后再写入一个元素可正常读回尺寸为 1

#### Scenario: 空批次写入不触发实体化
- **WHEN** 对处于空状态的实例执行"追加一个空批次"或"并入一个空映射"操作
- **THEN** 底层容器提供器未被调用，实例仍表现为不可变空态（读取尺寸 0、判空为真）

### Requirement: 惰性空集合并发首写全部保留（BREAKING）
N 个线程同时对同一新建惰性空容器实例各写入一个元素时，系统 MUST 保证全部写入被保留、无一丢失——原实现各线程各建各的底层表并互相覆盖（该缺陷直接影响事件通知器与服务发现监听等生产路径，修复属 **BREAKING**：依赖旧"后写覆盖"现象的用法将观察到数据不再丢失）。三种同族容器（列表、集合、映射）的首写原子性 MUST 一致。首写完成后 MUST 可立即读回全部已提交元素。

#### Scenario: 并发首写无丢失（列表/集合/映射三态一致）
- **WHEN** 8 个线程经同一起点栅栏同时对同一新建实例各写入一个互不相同的元素，重复多轮
- **THEN** 每轮结束后读回的元素数量恰为 8，任何元素都未丢失；列表、集合、映射三种实例表现一致

#### Scenario: 底层容器由提供器决定时以其语义为准
- **WHEN** 实例创建时指定了线程安全的底层容器提供器，并发首写完成后再并发追加
- **THEN** 换表仅发生一次、所有线程写入同一张由提供器创建的容器，持续并发写入仍全部保留

#### Scenario: 写后读闭环
- **WHEN** 单线程在并发首写结束后读取该实例
- **THEN** 可见全部已写入元素且无重复异常状态（集合语义下重复元素仍幂等）

### Requirement: 属性键同一 (命名空间, 名称) 恒等实例
同一 (命名空间, 名称) 组合的属性键，任意线程在任意时刻再次取得时 MUST 返回恒等（同一实例）；全局短名方式取得的键 MUST NOT 与任何命名空间键互相命中（原实现查询用短名导致跨命名空间劫持与同名称双实例，修复属 **BREAKING**：原先被错误合并的键将分离，读写必须使用同一取键入口）。通过任一次取得的键写入属性容器的值 MUST 能被另一次同 (命名空间, 名称) 取得的键读回。

#### Scenario: 同组重复取得恒等
- **WHEN** 先后两次以同一 (命名空间, 名称) 取得属性键
- **THEN** 两次返回同一实例，且键的短名保持为声明的名称

#### Scenario: 并发首次取得唯一实例
- **WHEN** 16 个线程同时对同一 (命名空间, 名称) 首次取键
- **THEN** 所有线程得到同一实例，无双实例

#### Scenario: 读写闭环跨取得实例生效
- **WHEN** 用第一次取得的键写入属性值，再用第二次取得的同名同空间键读取
- **THEN** 读回写入的值

### Requirement: 属性键命名空间隔离与聚合视图显式冲突（BREAKING）
不同命名空间下同名称的键 MUST 相互隔离：不得互相命中，且 MUST 各自可在同一属性容器独立存取互不干扰；全局短名键与命名空间键 MUST NOT 因创建先后顺序而融合。当同一属性容器内同时存在两个短名相同但命名空间不同的键的值时，按名聚合的视图 MUST 显式抛出重复名冲突异常失败，MUST NOT 静默丢弃或覆盖其中一个。

#### Scenario: 命名空间同名互不命中
- **WHEN** 分别以两个不同命名空间与同一名称取得键，再取得同名的全局短名键
- **THEN** 三者互不相同；无论创建顺序如何，后创建的键不会命中先前创建的异空间键

#### Scenario: 异空间同名键独立存取
- **WHEN** 用两个不同命名空间的同名键分别向属性容器写入不同值
- **THEN** 各自读回各自的值，互不覆盖

#### Scenario: 按名聚合显式冲突（错误路径）
- **WHEN** 同一属性容器内同时持有短名相同、命名空间不同的两个键的值，随后请求按名聚合视图
- **THEN** 聚合操作抛出重复名冲突异常并整体失败，不返回遗漏任一数据的静默结果；单键容器聚合正常返回

### Requirement: 元素按自身类标识收集的重复键后值胜出（BREAKING）
以元素自身类标识为键把元素流收集为映射时，重复键 MUST NOT 抛出异常（原实现重复注册直接抛合并异常，与单条注册的覆盖语义矛盾，修复属 **BREAKING**：原先必抛的场景现在返回后值胜出的映射），MUST 保留最后出现的元素为该键的值；无重复键时 MUST 一对一收录全部元素。

#### Scenario: 重复键后值胜出
- **WHEN** 流中包含两个同类的不同实例并按类标识收集
- **THEN** 收集成功不抛异常，结果中该键的值是流中最后出现的那个实例

#### Scenario: 无重复键完整收录
- **WHEN** 流中所有元素类标识互不相同
- **THEN** 结果映射的条目数与流元素数一致，键值对应正确

### Requirement: 空迭代序列耗尽必须抛异常（BREAKING）
系统提供的空迭代序列，其"是否还有下一元素" MUST 恒为假；"取下一元素"操作 MUST 按迭代器标准契约抛出无更多元素异常（原实现返回 null，违反平台迭代器契约，修复属 **BREAKING**：依赖 null 返回的调用方将改为收到异常）。

#### Scenario: 空序列取元素抛异常
- **WHEN** 对空迭代序列调用取下一元素操作
- **THEN** 抛出无更多元素异常，而非返回 null

#### Scenario: 重复耗尽稳定抛异常（错误路径）
- **WHEN** 连续多次对已耗尽的空迭代序列调用取下一元素
- **THEN** 每次均抛出无更多元素异常，"是否还有下一元素"始终为假

### Requirement: 散列取模锁槽全域哈希值正常加解锁
按键散列值取模定位锁槽的加锁工具 MUST 对整数域全部散列值（包括最小负整数与一般负值）正常定位并加解锁，MUST NOT 越界失败（原实现负散列值产生负索引直接异常）。释放 MUST 校验锁句柄归属：以不匹配句柄解锁 MUST 被显式拒绝。

#### Scenario: 极端散列值正常加解锁
- **WHEN** 以散列码恰为整数域最小值的键执行加锁后解锁，并再次加解锁
- **THEN** 两轮操作均正常完成，无越界异常

#### Scenario: 句柄不匹配解锁被拒（错误路径）
- **WHEN** 持有一个锁句柄，却以另一对象的句柄对当前键请求解锁
- **THEN** 解锁被拒绝并抛出锁句柄不匹配异常，原锁不被误释放

### Requirement: 监听器注册表移除真实生效且并发首注册不丢（BREAKING）
全局监听器注册表中移除监听器 MUST 真实移除（原实现移除被误写为追加，越删越多，修复属 **BREAKING**：原先"移除无效"的用法此后监听器不再收到事件）；注册后可按类型查询到该监听器。多个线程对同类型监听器并发首次注册时 MUST 全部保留、不互相覆盖。移除未注册过的监听器 MUST 无害返回。

#### Scenario: 注册可见且移除生效
- **WHEN** 注册一个监听器后按类型查询，随后执行移除再查询
- **THEN** 移除前查询命中，移除后查询不再命中，且注册表条目不增长

#### Scenario: 并发首注册全部保留
- **WHEN** 多个线程同时对尚无登记记录的同类型首次注册各自的监听器
- **THEN** 全部监听器均被保留，无一因首建表竞态丢失

#### Scenario: 移除未注册监听器无害（边界路径）
- **WHEN** 对从未注册过的监听器实例执行移除
- **THEN** 操作正常完成、不抛异常、注册表状态不变

### Requirement: 完成结果映射仅成功进入映射函数（BREAKING）
对全局完成结果执行值映射时：成功结果 MUST 以映射函数变换其值并保留原结果码与消息；失败结果 MUST NOT 调用映射函数，MUST 直接以空值透传失败及其原结果码与消息（原实现条件写反——只放失败进入、把空值喂给映射函数，修复属 **BREAKING**）。

#### Scenario: 成功结果值被变换且码保留
- **WHEN** 对一个携带值的成功完成结果应用值映射
- **THEN** 结果仍为成功、结果码不变，其值等于映射函数作用于原值得到的结果

#### Scenario: 失败结果不进映射函数（错误路径）
- **WHEN** 对一个失败完成结果应用值映射
- **THEN** 映射函数完全未被调用，结果仍为失败、结果码与消息透传原值、值为空
