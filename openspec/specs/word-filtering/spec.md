# word-filtering Specification

## Purpose

本能力定义敏感词过滤的命中、掩码与检测行为契约及其失败方向。该判定位于聊天审核热路径（网络层文本检查），直接决定违规内容是否放行：匹配语义（大小写不敏感、命中段全量掩码、跨词不误报、双通道结论一致）必须确定；未加载状态的透传行为（fail-open）作为显式契约入册并要求调用方先建立词表；首载失败必须显式失败、热更失败必须保留旧词表（fail-closed），杜绝"审核整体静默失效"这一原事故模式。

## Requirements

### Requirement: 命中词的全量掩码与无关字符保持
词表加载完成后，过滤 MUST 对内容中每个完整命中段实施全量掩码——长度为 N 的词 MUST 将其所在 N 个位置全部替换为掩码字符；未构成命中的字符 MUST 逐位保持原样，掩码前后内容总长度 MUST 不变；空输入 MUST 原样返回空，无命中输入 MUST 逐字符不变。

#### Scenario: 中英文词命中各自全量掩码
- **WHEN** 词表含中文词"敏感词"与英文词"外挂"，待处理内容为"这是敏感词啊"
- **THEN** 命中的 3 个字符全部被掩码，输出"这是***啊"，前后无关字符不动；含词内容经检测判为命中，不含词的正常聊天内容判为不命中

#### Scenario: 空输入与干净输入原样通过
- **WHEN** 分别以空串与不含任何敏感词的文本"hello"请求掩码
- **THEN** 空串返回空、"hello"逐字符不变，均不抛异常，检测对两者均判不命中

### Requirement: 大小写不敏感匹配且掩码落在原位置
词命中判定 MUST 忽略大小写：词表以小写形态装载时，输入中的大写或混合大小写形态 MUST 同样命中；掩码 MUST 施加于命中片段在原文中的原位置、按原长度替换，MUST NOT 改变非命中字符的大小写或位置。

#### Scenario: 大写输入命中小写词表
- **WHEN** 词表含小写"abc"，输入为"XXABCxx"，掩码字符为星形态
- **THEN** 输出"XX***xx"——中间 3 个大写字符原位被掩码，两侧小写字符原样保留

#### Scenario: 混合大小写相邻片段仍按不敏感语义判定
- **WHEN** 输入"xxABdE"，词表含"abc"与"de"
- **THEN** 忽略大小写后按连续完整词判定："ab"+"d"不构成词、尾部"dE"命中"de"，检测判为命中

### Requirement: 跨词边界不误报
过滤 MUST 仅识别词表词的连续完整命中；前一命中词的尾字符与后续文本的首字符拼接后仅构成另一词的前缀而非完整词时，MUST NOT 判为命中、MUST NOT 掩码；命中判定结束后 MUST 自命中段之后的位置继续扫描，不漏扫后续词。

#### Scenario: 相邻片段仅前词完整命中
- **WHEN** 词表含"abc"与"de"，输入为"xxabcdxx"
- **THEN** 仅"abc"三个字符被掩码，其后单独的"d"不被掩码（"de"需连续"e"才成词），输出"xx***dxx"——掩码字符数恰为 3

#### Scenario: 仅成词前缀的字符序列一律不命中
- **WHEN** 输入含词表某词的部分前缀字符但从未连续凑成完整词
- **THEN** 检测判不命中，掩码输出与输入逐字符相同

### Requirement: 检测与掩码双通道结论一致
对同一输入与同一词表，检测通道与掩码通道 MUST 给出一致结论：检测报命中当且仅当掩码改变了内容；MUST NOT 出现"检测称有词而掩码无处可掩"或"掩码动了内容而检测判干净"的分叉。两通道 MUST 基于同一份已加载词表。

#### Scenario: 命中内容双通道同向
- **WHEN** 对含完整敏感词"敏感词"的句子分别执行检测与掩码
- **THEN** 检测返回命中，掩码产生与命中位置对应的改变

#### Scenario: 边界输入双通道同向
- **WHEN** 对跨词边界的近邻误报输入（如"xxabcdxx"）与完全干净输入分别执行两通道
- **THEN** 前者检测命中（因"abc"成词）且掩码恰掩 3 字符，后者检测不命中且掩码逐字符不变——两通道对同一输入的命中/不命中结论恒一致

### Requirement: 未加载实例的显式 fail-open 与调用方先装载契约
词表尚未建立成功的过滤实例，其行为 MUST 确定：掩码通道原样透传返回、检测通道一律判不命中——此 fail-open 方向作为显式契约入册并 MUST NOT 抛异常。据此，消费方契约同步钉死：将过滤挂入聊天审核等热路径前 MUST 先完成词表装载，MUST NOT 以未装载实例"无敏感词"的判定结果面对流量。

#### Scenario: 已装载实例按词表判定
- **WHEN** 词表装载完成后对含词内容执行掩码与检测
- **THEN** 判定与掩码均按词表生效

#### Scenario: 未装载实例透传且判否
- **WHEN** 从未成功装载词表的过滤实例被直接请求掩码"敏感词"与检测"敏感词"
- **THEN** 掩码原样返回"敏感词"，检测判不命中，无异常抛出（fail-open 显式、可预期）

#### Scenario: 审核装配以装载成功为前置
- **WHEN** 聊天审核挂载点在启动流程中装配过滤能力
- **THEN** 只有在词表首载成功后才接受流量；首载失败时该装配按首载契约显式失败，绝不带着"全部透传"的未装载状态上线

### Requirement: 首载读取失败必须显式失败
词表首次装载时若内容不可读（IO 异常或数据流读取失败），MUST 将异常显式上抛给装载发起方，MUST NOT 以空词表替代完成首载——"带病启动的空表成功"状态 MUST NOT 存在（原实现允许空词表装载成功，该场景 MUST NOT 再现，BREAKING 收口）。首载成功 MUST 一次性建立完整词表供后续判定。

#### Scenario: 首载成功建立完整词表
- **WHEN** 词表文件内容可读，首载完成
- **THEN** 词表整体生效，检测与掩码立即按该表判定

#### Scenario: 首载 IO 失败异常上抛
- **WHEN** 首次装载过程中数据流读取抛出 IO 异常
- **THEN** 该异常上抛至调用方（可据此失败快），实例不进入"首载成功但词表为空"的状态

### Requirement: 热更读取失败保留旧词表（fail-closed）
词表热更（已装载成功后的重新读取）时若内容不可读，系统 MUST 保留旧词表并继续以完整旧表提供检测与掩码（fail-closed），MUST NOT 清空或替换词表——该判定位于聊天审核热路径，热更失败方向被钉死为"继续用旧表"，原实现"清空致审核整体失效"的 fail-open 事故 MUST NOT 再现（BREAKING 收口）。瞬时失败之后的下一次热更成功 MUST 以新词表语义替换生效。

#### Scenario: 热更瞬时失败旧表照常服役
- **WHEN** 词表已装载，随后一次重载的数据流读取抛出 IO 异常
- **THEN** 旧词表保留：含词句子仍判命中、掩码仍按旧表全量生效，无任何"清空后全放行"窗口

#### Scenario: 失败后的成功热更照常替换
- **WHEN** 一次热更读取失败之后的下一次热更成功读到新内容
- **THEN** 词表按新内容整体替换，新表与旧表差异对后续判定生效，先前失败不造成永久污染

### Requirement: 掩码字符缺省回落
掩码字符 MUST 可配置：配置提供非空白文本时以其首字符为掩码字符；配置为空白文本或未提供时 MUST 回落到默认掩码字符，初始化与使用 MUST NOT 因此崩溃（原实现对空白/未提供形态直接取字符必抛异常，该崩溃面 MUST NOT 再现）。

#### Scenario: 自定义掩码字符生效
- **WHEN** 以非空白掩码字符配置过滤并掩码一段含词内容
- **THEN** 命中段以该自定义字符替换

#### Scenario: 空白或未提供回落默认字符
- **WHEN** 分别以空白串与未提供（null）配置掩码字符，随后装载词表并执行掩码
- **THEN** 两者均不崩溃，命中段以默认掩码字符替换（如"xxabcxx"输出"xx***xx"），检测判定不受影响
