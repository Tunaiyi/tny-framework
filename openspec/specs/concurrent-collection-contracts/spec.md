# concurrent-collection-contracts Specification

## Purpose

并发集合契约覆盖写时复制映射的读侧快照语义、有界固定容量映射的容量精确性、映射后备集与不可变键值条目在迭代、移除、判等上的基础行为，以及映射构建器产出独立可变副本的装配语义。本能力把这些此前仅隐含于实现、彼此矛盾的休眠行为立约为外部可观察、可测试的契约：读侧视图按"获取时刻快照"冻结且只读，有界映射恰容纳上限条数并驱逐最旧，后备集与条目遵循 JDK 集合与映射条目的标准约定，构建器产物与源映射双向隔离。

## Requirements

### Requirement: 写时复制映射的读侧集合视图为获取时刻快照且严格只读
写时复制映射的按键点读、规模与包含判断 MUST 反映最新已提交的写入；而键集、值集、条目集等批量读视图 MUST 呈现获取时刻的快照：视图取得后映射发生的后续写入 MUST NOT 出现在该视图中，MUST 出现在其后新取得的视图中。视图 MUST NOT 支持任何修改操作——经视图迭代器移除元素、经条目改写值等尝试 MUST 显式失败，MUST NOT 写入已与映射脱钩的旧副本造成"看似生效、实际丢失"（**BREAKING**：修复前视图为可修改的底层活动视图，修改落空且与写时复制模型矛盾）。对已获取视图的迭代 MUST 在无锁并发下安全完成，MUST NOT 因其他线程写入而抛出并发修改异常。

#### Scenario: 获取后写入对旧视图不可见、对新视图可见
- **WHEN** 获取映射的条目集视图，随后向映射新增一条并移除一条，再重新获取条目集视图
- **THEN** 旧视图内容保持获取时刻的冻结状态（不含新增、仍含被移条目）；新视图不含被移条目且包含新增条目

#### Scenario: 视图修改尝试显式失败且不丢失写入
- **WHEN** 对已获取的键集视图迭代器发起移除、或对条目集视图中的条目发起值改写
- **THEN** 操作以不支持修改的异常显式失败，映射自身内容不因该尝试发生任何变化，也不存在被悄悄写入的脱钩副本

#### Scenario: 并发写入下快照迭代安全（边界路径）
- **WHEN** 一个线程遍历已获取的条目集视图期间，另一线程持续对映射执行写入
- **THEN** 遍历完整结束、所见恒为获取时刻的内容，全程无并发修改异常，映射的按点读仍返回最新写入值

### Requirement: 有界固定容量映射恰容纳上限条数并按插入序驱逐最旧
声明容量上限为 N 的有界映射 MUST 恰好容纳 N 条：连续写入不超过 N 个互异键时全部在位、不丢任何一条（**BREAKING**：修复前存在容量差一，上限 N 仅存 N-1 条、上限 1 存入即被清空）。写入第 N+1 个互异键时 MUST 驱逐按插入顺序最早的一条并保留新条目，映射规模恒不超过 N。以上限非正数构造 MUST 显式失败。

#### Scenario: 上限为一时可存一条
- **WHEN** 创建上限为 1 的有界映射并写入一个键值对
- **THEN** 该条目在位可读，映射规模为一，未出现"存入即清空"

#### Scenario: 越上限写入驱逐最旧且保留其余
- **WHEN** 向上限为 5 的有界映射按序写入 10 个互异键
- **THEN** 映射规模为 5，在位者为最后写入的 5 个键且按插入序排列，最早写入的 5 个键被逐一驱逐

#### Scenario: 非正上限构造失败（错误路径）
- **WHEN** 以零或负数作为容量上限构造有界映射
- **THEN** 构造显式失败并给出非法参数的错误信号，不产出行为未定义的实例

### Requirement: 映射后备集遵循集合契约并与后备映射键集一致
以映射键为存储的后备集 MUST 满足：添加元素等价于向后备映射写入该键（重复添加不改变映射且返回"未新增"）、移除元素等价于按键移除、包含判断与规模恒等于后备映射的键内容；经迭代器移除 MUST 从后备集中生效并同步反映到后备映射；两个后备集按内容判等——互含对方全部元素则相等，散列码 MUST 由元素内容决定而非实例身份；对不可变后备映射发起添加/移除 MUST 显式失败而非静默无效。

#### Scenario: 增删查与后备映射键内容同步
- **WHEN** 向以键为 a、b 的映射为底的后备集添加 c、移除 a，随后查询包含与规模
- **THEN** 集合含 b、c 且规模为 2，后备映射的键集合同为 b、c；对重复添加 c 的再次添加返回"未新增"且内容不变

#### Scenario: 迭代器移除生效于后备映射
- **WHEN** 通过后备集迭代器移除当前遍历到的元素后，查询集合与后备映射
- **THEN** 该元素从集合与后备映射同时消失，不存在"视图删了、映射没删"的分叉

#### Scenario: 按内容判等与不可变后备的修改失败（错误路径）
- **WHEN** 用键内容相同但实例不同的两个映射分别构造后备集并判等；另对以只读映射为底的后备集发起添加
- **THEN** 两后备集判等相等且散列码一致；发起的添加以不支持修改的异常显式失败

### Requirement: 不可变键值条目遵循标准条目判等且拒绝改写
独立持有的不可变键值条目 MUST：取键取值恒返回构造时的引用；值改写操作 MUST 显式失败；与其他条目判等 MUST 按"键相等且值相等"的内容语义成立——与映射内部条目、另一不可变条目比较结果一致，MUST NOT 退化为按实例身份判等；散列码 MUST 由键与值的内容确定，内容相同的条目散列码相同；空键或空值 MUST 能正常参与取值、判等与哈希，判等与哈希 MUST NOT 因空侧引用而抛出错误。
（修复前条目未按内容实现判等与哈希，作为映射产物进入比较语义的场景静默失真。）

#### Scenario: 内容相同的条目判等相等且哈希一致
- **WHEN** 构造两个键值分别相同的不可变条目，并分别与含相同内容的映射条目判等
- **THEN** 三者两两判等成立，散列码互相等

#### Scenario: 改写值显式失败（错误路径）
- **WHEN** 对不可变条目发起值改写
- **THEN** 操作以不支持操作异常失败，条目的键与值保持构造时引用不变

#### Scenario: 空键空值参与判等与哈希正常（边界路径）
- **WHEN** 构造空值条目与空键条目，分别取值、互相判等、计算散列码
- **THEN** 取值返回空引用不抛异常；同为空侧内容的相等条目判等成立、散列码一致，全程无空指针类错误

### Requirement: 映射构建器的内容入口真实装载且产物为独立可变副本
映射构建器的每个内容入口 MUST 真实装载其入参内容：以既有映射或映射提供者构造时，该映射的当前全部条目 MUST 成为构建器初始内容；构建器后续的增删改 MUST NOT 回写污染源映射，源映射在其后发生的修改 MUST NOT 出现在构建器及其产物中——产物为一份独立的可变映射副本（**BREAKING**：修复前内容入口静默丢弃入参或直取源引用造成双向污染；不携带任何内容的"引用标记"型入参入口属死抽象清理，移除后不再存在）。空构建器产物 MUST 为不含任何条目的可用映射。

#### Scenario: 从源映射出发双向隔离
- **WHEN** 以含条目 (k1→v1) 的映射构造构建器，经构建器追加 (k2→v2) 后产出映射，再向源映射写入 (k3→v3)
- **THEN** 产物恰含 k1、k2 两条，源映射含 k1、k3 两条且从未被构建器动作污染，产物不含 k3

#### Scenario: 静默丢弃内容的入口不再存在（错误路径）
- **WHEN** 审视构建器全部公开内容入口，以空内容映射与提供器构造并直接产出
- **THEN** 不存在"传入内容却被静默忽略产出空映射"的入口；空产物仅来自确以空映射出发的构造，空构建器直接产出规模为零的可用映射

#### Scenario: 多次产物共享最新内容（边界路径）
- **WHEN** 构建器先产出一份映射，随后追加新条目再次产出
- **THEN** 两次产出均为可变映射且各按产出时刻的内容呈现可独立修改，对第二次产出的修改不影响第一次产出
