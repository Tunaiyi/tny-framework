# worker-command-boxes Specification

## Purpose

命令盒家族是 actor、会话与频率任务的串行调度底座：命令经盒队列受理、由执行器心跳或唤醒驱动处理，延迟与循环命令按时间语义推进，双缓冲队列隔离提交与消费两侧。该簇长期无测试覆盖、语义未闭合——未到点的新命令被立即执行、缓冲切换恒为无操作、限步判据恒假、注销误写为注册、心跳只发空通知、关闭链残缺，一旦启用即静默失效。本能力把修复后应然行为钉死为可观测契约：每命令至多执行一次且到点才执行、单轮限步真实生效、回投命令不丢不重、注册/注销/关闭链闭环、提交与排空竞态无丢唤醒，并覆盖队列满、拒绝与重复注销等错误路径。

## Requirements

### Requirement: 延迟命令到点才执行且执行至多一次
携带延迟时间点的命令在该时间点到达之前 MUST NOT 执行——受理轮询与空转扫过 MUST NOT 触发其业务动作；时间点到达后 MUST 恰好执行一次，执行完成即标记结束并从待处理集合移除，MUST NOT 因后续轮次再次执行。对执行时间点的调整入口（提前为立即、重新设定延迟、指定绝对时点）以调整后时点为唯一判据生效。（**BREAKING**：修复前"未到延迟的新命令立即执行"，属判据取反缺陷，全仓无正确依赖该行为的调用点；修复后此类任务顺延至到点执行。）

#### Scenario: 未到点的命令零执行且不丢失
- **WHEN** 提交一个时间点在未来数十毫秒后的延迟命令，其间频率盒完成若干轮处理
- **THEN** 业务动作执行次数为 0，命令仍在盒内待处理，未被丢弃也未被提前执行

#### Scenario: 到点当轮恰好执行一次
- **WHEN** 时间点到后的下一轮处理扫过该命令
- **THEN** 动作恰好执行一次，命令标记结束并从待处理集合移除

#### Scenario: 已结束命令的重复执行请求无效（边界路径）
- **WHEN** 同一已结束命令在后续轮次或同轮迭代中再次被执行请求
- **THEN** 动作执行总次数保持为 1，无任何二次副作用

#### Scenario: 提前为立即的调整生效（边界路径）
- **WHEN** 一个未到点的延迟命令被调整入口置为当前时点
- **THEN** 其后最近一轮处理即执行该命令

### Requirement: 循环命令相邻执行间隔不早于声明间隔且终止信号即止
循环命令首次执行前遵循延迟命令的"到点才执行"规则；每次执行完成后按动作声明的下一间隔重排下次时点，相邻两次实际执行的时间间隔 MUST NOT 早于该声明间隔——因轮询粒度而晚于间隔是允许的，提前则违反契约。动作返回终止信号时命令 MUST 标记结束并退出调度，此后轮次执行次数恒为 0；某一轮执行抛出异常 MUST NOT 使循环无声停摆——命令仍按声明间隔重排，且该异常 MUST 可观测（向上抛出或告警留痕），MUST NOT 被静默吞没。（**BREAKING**：修复前间隔形同虚设、每轮重复执行。）

#### Scenario: 多轮观测下间隔真实生效
- **WHEN** 一个声明固定间隔的循环命令被连续处理多个轮次，记录每次执行时刻
- **THEN** 任意相邻两次执行的间隔不小于声明间隔，间隔窗口内不出现额外执行

#### Scenario: 终止信号恰执行一次后退出
- **WHEN** 循环命令在动作中返回终止信号
- **THEN** 该命令累计执行次数恰为 1，其后任何轮次不再执行它

#### Scenario: 抛异常的轮次重排且异常可观测（错误路径）
- **WHEN** 循环命令某一轮动作抛出运行时异常
- **THEN** 异常被抛出或告警留痕，命令按声明间隔进入下一轮重排而非静默消失，后续轮次仍观测到其执行

### Requirement: 频率盒单轮处理范围以轮初快照为限且回投不进入本轮
频率盒每一轮的处理集合在该轮开始时按队列存量固定：本轮至多处理该轮开始时已在队列中的命令，轮次进行期间新受理的命令 MUST 留待下一轮；本轮执行计数 MUST NOT 超过轮初存量（限步判据 MUST 真实生效——修复前判据恒假致单轮无界消费）。本轮执行后仍未完成、需要再次调度的命令 MUST 回投到下一轮视角（不在本轮被再次扫到）：同一命令在同一轮内至多执行一次，回投 MUST NOT 使本轮迭代永动或重复执行。

#### Scenario: 处理中新受理的命令不进入本轮
- **WHEN** 频率盒开始一轮处理，期间另一线程持续受理新命令
- **THEN** 本轮执行数不超过开始时的队列存量，新受理命令在下一轮被执行

#### Scenario: 未完成命令回投后同轮不再执行
- **WHEN** 本轮某命令执行后仍未完成需要重排
- **THEN** 该命令本轮执行次数恰为 1，本轮 drain 循环不会再次取到它，下一轮继续处理

#### Scenario: 存量全部完成的轮次干净收口（边界路径）
- **WHEN** 一轮处理把队列中全部命令执行至完成
- **THEN** 队列与待处理集合清空、盒判空成立，本轮统计（执行数、用时）反映真实值而非残留上一轮数据

### Requirement: 开关队列切换真实生效且在途命令不丢不重
以双缓冲分离提交与处理的命令盒每轮 MUST 真实翻转缓冲方向：切换后新受理的命令进入当前接收缓冲，本轮处理对象为上一轮的接收缓冲；本轮执行后未完成而需重排的命令 MUST 回投到当前接收缓冲、仅下一轮被取到。切换与回投 MUST NOT 丢失任何已受理命令、MUST NOT 使同一命令在同一轮执行两次——对同一批已受理命令，最终执行总次数 MUST 等于受理次数（不丢不重）。清空与判空 MUST 覆盖两个缓冲。（**BREAKING**：修复前切换恒为无操作——处理侧被覆写回原缓冲，本轮重投的命令同轮即被再次取到。）

#### Scenario: 切换后方向翻转
- **WHEN** 第一轮受理并处理的命令在切换后，第二轮新受理一批命令
- **THEN** 新命令落入另一缓冲、在第三轮被处理，第二轮的执行集合不含它们

#### Scenario: 未切换完成期间的受理不丢失（错误/并发路径）
- **WHEN** 多个线程在处理线程反复切换缓冲的同时持续受理命令，随后停止提交并处理若干轮
- **THEN** 全部已受理命令每恰被执行一次：既无命令永久滞留，也无命令被执行两次

#### Scenario: 清空覆盖双缓冲（边界路径）
- **WHEN** 两个缓冲中各有待处理命令时执行清空
- **THEN** 两缓冲均无残留、盒判空为真，此后处理轮次零执行

### Requirement: 提交标志与排空竞态窗口不丢唤醒
命令盒"有存量→置提交标志→唤醒工作器"的提交流程与工作线程"排空→清标志"的完成流程之间的竞态窗口 MUST NOT 吞没唤醒：任何在清标志动作之前已受理并提交的命令，只要工作器存活或此后恢复运行，MUST 在有限轮次内被处理，MUST NOT 滞留到依赖下一次外部提交才前进。工作器停止期间受理的命令 MUST 保留在盒内不丢失，待重新绑定或恢复后处理。

#### Scenario: 空盒单次提交即被处理
- **WHEN** 盒处于空闲且仅提交一条命令
- **THEN** 该命令被执行，无需任何后续提交触发

#### Scenario: 数百轮提交-排空竞速零丢唤醒（错误/压力路径）
- **WHEN** 生产线程持续受理+提交、工作线程同盒竞速排空数百轮后停止提交
- **THEN** 全部已受理命令在有限轮次内执行完毕，执行总数与受理总数一致，无滞留

#### Scenario: 停止期间命令滞留不丢失（边界路径）
- **WHEN** 工作器停止运行期间向盒内受理命令
- **THEN** 命令保留在队列中且不被执行；工作器恢复或盒重新绑定后全部被处理

### Requirement: 执行器线程内受理直接内联执行且受理结果诚实
绑定工作器后的命令盒受理命令时：若受理线程正是工作器的执行线程，命令 MUST 在该线程内直接执行（不入队、不等待唤醒），受理返回"已处理"；否则走"入队+提交"路径。工作器身份判定 MUST 真实反映当前线程与执行线程的一致性，MUST NOT 恒为否定致内联路径永不可达。受理结果 MUST 诚实：队列满、下游拒绝或工作器已关闭（终态）时，MUST 返回失败或抛出显式异常，MUST NOT 静默丢弃命令却虚报成功；已关闭时的失败受理 MUST 回滚入队（命令不滞留盒内、不被后续执行）。停止≠关闭——工作器仅停止（未关闭）时受理按"停止期间滞留不丢失"场景返回滞留成功，本条失败面只覆盖队列满/下游拒绝/已关闭三种形态。修复前工作器线程身份判定恒为否定，"当前线程直执行"优化永不可达——工作器线程内的嵌套提交也要排队等下一轮，本条恢复其声明的即时性。

#### Scenario: 工作器线程内受理即刻内联执行
- **WHEN** 执行线程在处理一条命令的过程中受理另一条新命令
- **THEN** 新命令在同线程内立即执行完毕，盒队列存量不因它增长

#### Scenario: 非执行线程受理走排队路径
- **WHEN** 外部线程向同一盒受理命令
- **THEN** 命令入队并触发提交，由执行线程稍后处理，受理方线程不执行该命令

#### Scenario: 有界队列满显式拒绝（错误路径）
- **WHEN** 盒底层队列已满时再次受理命令
- **THEN** 受理返回失败或抛出显式异常，命令未被执行也未被静默接收；腾出容量后新受理恢复正常

#### Scenario: 关闭终态的受理显式失败并回滚（错误路径，与停止滞留划界）
- **WHEN** 执行器已关闭（终态，非停止）后向绑定的命令盒受理命令
- **THEN** 受理返回失败，命令被回滚出盒不滞留、不被任何后续路径执行；同一形态在工作器仅停止（未关闭）期间仍为滞留成功（停止≠关闭）

### Requirement: 注册绑定注销链闭环——失败不留注册、注销幂等
注册命令盒到执行器 MUST 两步齐备方可宣告成功：绑定工作器且加入注册列表。绑定失败（盒已绑定于其他工作器）MUST NOT 加入注册列表、MUST NOT 部分生效，注册 MUST 返回显式失败——MUST NOT 出现"返回成功但未注册、命令静默无人处理"的残留态。注销 MUST 从注册列表移除并解除绑定；重复注销与注销从未注册的盒 MUST 返回失败且无任何副作用（幂等，不得误伤列表内其他盒）。父盒对子盒的并发注册 MUST NOT 因集合惰性初始化的竞态丢失任何子盒；父盒解除绑定时全部子盒 MUST 级联解除。

#### Scenario: 注册-注销-重注册闭环
- **WHEN** 一个新盒注册到执行器、执行若干轮后注销、再重新注册
- **THEN** 三次操作均返回成功；注销期间其积压不被处理，重注册后恢复被处理

#### Scenario: 已绑定的盒重复注册显式失败（错误路径）
- **WHEN** 一个已绑定执行器 A 的盒尝试注册到执行器 B
- **THEN** 注册返回失败，该盒不在 B 的注册列表中，A 的绑定与其队列积压不受任何影响

#### Scenario: 重复注销幂等（错误路径）
- **WHEN** 同一个盒连续注销两次，以及对从未注册的盒执行注销
- **THEN** 仅第一次返回成功；后续调用返回失败、不抛异常，列表内其他注册盒不被误移除

#### Scenario: 并发注册子盒零丢失（边界路径）
- **WHEN** 多个线程同时向同一父盒注册各自的子盒
- **THEN** 父盒的子盒集合包含全部已注册的子盒，父盒每轮处理时每个子盒均被处理

### Requirement: 频率执行器心跳真实驱动全部注册盒
频率执行器的每个心跳周期 MUST 实际驱动（处理）当前注册列表中的每个命令盒，MUST NOT 仅发出空通知使注册盒永不被处理；注册盒的积压命令随心跳轮次递减直至清空。注销后的盒 MUST 不再被心跳处理。某一盒在一轮处理中抛出异常 MUST NOT 冻结心跳——异常可观测（抛出或告警留痕），其余注册盒当轮继续处理、后续轮次照常推进。

#### Scenario: 注册后积压随心跳被处理
- **WHEN** 一个含若干积压命令的盒注册到运行中的频率执行器，等待数个心跳周期
- **THEN** 盒的积压命令被逐步执行（存量可观测地减少直至清空）

#### Scenario: 注销后不再被心跳处理（错误路径）
- **WHEN** 盒注销后再向它受理新命令
- **THEN** 该盒的积压不因心跳而减少，新命令保持待处理状态

#### Scenario: 单盒异常不冻结心跳（边界路径）
- **WHEN** 某盒处理中抛出异常，注册列表中还有其他盒
- **THEN** 异常可观测，其他盒在同一轮及后续轮仍被正常处理，心跳线程存活

### Requirement: 执行器启动与关闭链闭环——无泄漏线程与未关池
执行器关闭 MUST 停止其心跳线程并关闭其自管理的全部业务执行资源（含业务线程池），MUST 幂等——重复关闭不抛异常、不产生新副作用；关闭后所有在途与积压处理的去向 MUST 确定可观测。启动 MUST NOT 重入泄漏：已启动状态下再次启动 MUST 显式拒绝，或先终止旧心跳再启动新心跳——MUST NOT 出现"旧心跳线程因代际标志被覆写而永不退出、与新生成者双倍速率同时驱动注册列表"的泄漏态（**BREAKING**：关闭语义补全——修复前关闭仅停心跳、业务池与重入泄漏的旧线程永驻）。关闭完成后向该执行器注册 MUST 返回显式失败，MUST NOT 虚报注册成功使命令静默滞留无人处理。

#### Scenario: 关闭链收口全部自管资源
- **WHEN** 执行器正常运行一段时间后调用关闭，随后重复调用关闭
- **THEN** 心跳线程终止、业务池不再接受任何任务、重复关闭静默幂等；关闭前已受理并完成执行的动作留有确定记录，关闭不再改变

#### Scenario: 重入启动不泄漏旧心跳（错误路径）
- **WHEN** 执行器经历"启动→关闭→再启动"或误对运行中执行器再次启动，随后关闭
- **THEN** 全过程中存活的心跳线程数不超过 1 个代际，最终全部终止；注册列表不被新旧两代心跳同时以双倍速率处理

#### Scenario: 关闭后注册显式失败（错误路径）
- **WHEN** 执行器关闭后尝试把新盒注册到它
- **THEN** 注册返回失败，盒未被绑定、未进入列表，调用方可感知并改道
