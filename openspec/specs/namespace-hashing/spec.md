# namespace-hashing Specification

## Purpose

命名空间分片哈希组件让部署方从一组内置哈希算法中选定一种，把节点名与路由键折算成落在声明取值域内的整数槽位。本能力约定各算法选项对外可见的行为：输出宽度、取值范围、跨调用确定性、种子的参与方式，以及新增选项不得影响既有选项的结果。

## Requirements

### Requirement: 算法集提供三十二位宽度的 CityHash 选项且输出确定
命名空间分片哈希组件的算法集 SHALL 提供一个三十二位宽度的 CityHash 算法选项。调用方选定该选项后，对同一文本键与同一种子重复计算，返回值 MUST 逐次相等且跨进程重启保持稳定；返回值 MUST 落在无符号三十二位整数范围（0 到 4294967295）内；该选项向使用方声明的取值上界 MUST 为 4294967295。

#### Scenario: 同一输入的哈希结果跨调用一致（正常路径）
- **WHEN** 对文本键 "ABC" 与种子 0 使用三十二位 CityHash 选项连续计算两次，并在重新发起的独立调用中再计算一次
- **THEN** 三次返回值逐一相等，且都在 0 到 4294967295 之间

#### Scenario: 非 ASCII 输入有确定取值（错误路径）
- **WHEN** 对包含中文与表情符号的文本键计算该选项的哈希
- **THEN** 计算不抛出异常，返回一个落在上述范围内的确定值；两个仅字节内容不同的中文文本返回不同的值

### Requirement: 三十二位 CityHash 选项与官方参考实现逐值一致
三十二位 CityHash 选项在种子为零时的哈希值 MUST 与 Google CityHash 参考实现（论文与开源实现 city.cpp 中定义的 32 位 CityHash 函数）对同一 UTF-8 字节序列的输出逐值相等；它 MUST NOT 是其他宽度 CityHash 结果截断或折叠而来的替代值。

#### Scenario: 与参考实现黄金向量逐一相等（正常路径）
- **WHEN** 对一批预先从参考实现固化的样本键（覆盖空串、短于四个字节、四到二十四字节、二十四字节以上各长度段）以种子 0 计算哈希
- **THEN** 每个样本的返回值与固化的参考值逐位相等

#### Scenario: 拒绝以折叠值冒充参考值（错误路径）
- **WHEN** 把该选项对样本键的输出与"六十四位 CityHash 结果的高三十二位或低三十二位"分别比对
- **THEN** 至少对若干样本键二者不相等，证明该选项走的是独立的 32 位算法而非截断折叠

### Requirement: 种子参与方式遵循组件既有的键拼接约定且不扰动其他选项
三十二位 CityHash 选项对种子的处理 MUST 遵循组件既有的约定：所选官方参考算法本身不接受种子参数，因此非零种子 MUST 以"把种子文本拼接到键之后再计算"的方式参与哈希，使同一键在不同种子下得到不同结果；该约定与组件内既有不支持原生种子的算法选项行为一致。新增该选项 MUST NOT 改变算法集中任何既有选项的哈希结果，也 MUST NOT 改变组件的缺省选项。

#### Scenario: 非零种子改变哈希结果（正常路径）
- **WHEN** 对同一文本键分别以种子 0 与种子 7 计算三十二位 CityHash 选项的哈希
- **THEN** 种子 7 的返回值等于参考实现对"键文本拼接种子文本后的序列"的计算结果，且与种子 0 的返回值不同

#### Scenario: 既有选项与缺省选项不受扰动（向后兼容路径）
- **WHEN** 引入新选项前后，对同一批样本键分别用算法集中既有的各选项与缺省选项计算哈希
- **THEN** 每个既有选项的返回值逐一不变，缺省选项仍为原选项

### Requirement: 命名空间哈希构件的传递依赖面不得携带使用方未选用的算法库
命名空间哈希构件发布后，下游工程通过它获得的编译期与运行期传递依赖 MUST NOT 包含 `cn.hutool:hutool-core`：该库既不是组件内任何算法选项的声明实现，也未向使用方提供可选能力，其出现在依赖面即构成无关承载。组件的发布 POM MUST 只声明组件确实在用的算法族库（Apache Commons Codec 与 zero-allocation-hashing）及项目内依赖。

#### Scenario: 升级后依赖面收缩且既有选用不受影响（正常路径）
- **WHEN** 下游工程把命名空间哈希构件升级到本变更后的版本，检视其解析出的编译类路径与运行类路径，并照常使用算法集中任一 CityHash 选项对原有键计算哈希
- **THEN** 两个类路径中均不出现 `cn.hutool:hutool-core`；CityHash 选项仍可计算，返回值落在其声明取值域内且跨调用确定

#### Scenario: 依赖 hutool 编译面的下游必须自备声明（错误路径）
- **WHEN** 某下游工程过去借助 api 传递编译面直接引用 hutool 的工具类，在未自行声明该依赖的情况下升级到本变更后的版本并编译
- **THEN** 编译当场以未解析引用失败并指出缺失坐标，而不是静默换用其他实现；该下游须在自身构建中显式声明所需依赖（组件未承诺向编译面泄漏任何未选用库）

### Requirement: CityHash 两档选项实现接替后保持各自参考算法语义与取值域契约
CityHash 算法族选项在替换底层实现后，三十二位档 MUST 继续与 Google CityHash 参考实现定义的 32 位函数对同一 UTF-8 字节序列的输出逐值一致，其声明取值上界 MUST 保持为 4294967295；六十四位档 MUST 采用带种子形态的 CityHash 64 位参考语义（种子原生参与计算而非键拼接），其声明取值上界 MUST 保持为长整型最大值。经需求方裁定，两档选项对同一输入的返回值允许与本变更前的中间实现形态不同，本规格不对其施加零漂移承诺；但任一档的返回值 MUST 跨调用、跨重启确定，算法集中其他选项与缺省算法的结果 MUST 不因本变更而改变。

#### Scenario: 六十四位档种子原生参与且结果确定（正常路径）
- **WHEN** 使用六十四位 CityHash 选项对同一文本键分别以种子 0 与种子 7 各连续计算两次
- **THEN** 同一种子下两次结果相等；种子 7 的结果与该键在参考实现"带种子 64 位 CityHash"函数下的输出一致，且不同于种子 0 的结果

#### Scenario: 三十二位档与参考实现黄金向量一致且与六十四位截断可区分（正常路径）
- **WHEN** 对一批覆盖各长度段的样本键以种子 0 计算三十二位 CityHash 选项，与固化的参考实现向量比对，并与六十四位档结果的高低 32 位截断值比对
- **THEN** 与参考向量逐位相等；至少对若干样本键二者不等，证明其非 64 位结果折叠

#### Scenario: 非 ASCII 输入与取值上界在接替后不变（错误路径与边界）
- **WHEN** 用替换实现后的两档选项对含中文与表情符号的键计算哈希，并读取两档各自声明的取值上界
- **THEN** 计算不抛异常且返回确定值；三十二位档返回值始终在 0 到 4294967295 区间且上界报告为 4294967295，六十四位档上界报告仍为长整型最大值
