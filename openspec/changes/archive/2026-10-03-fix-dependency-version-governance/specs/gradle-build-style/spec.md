# Spec Delta

## MODIFIED Requirements

### Requirement: 依赖版本与坐标由单一事实源管理
依赖的版本号 SHALL 只出现在两处：`gradle.properties`（各 BOM 级大头版本，供插件声明与 BOM 导入语句取用）与 `gradle/libs.versions.toml` 版本目录（第三方依赖坐标与版本的具名声明面）。模块 `build.gradle` 中的依赖声明 MUST 只以版本目录的具名访问器表达（形如 `api libs.xxx` 与 `api project(':xxx')`）；MUST NOT 出现手写的组号加工件名坐标字符串，MUST NOT 拼接版本号字面量，MUST NOT 给已由 BOM 统一管理的依赖追加版本段。版本目录 MUST 是唯一的具名引用表：MUST NOT 再以 Groovy ext 映射或其他机制另立第二套坐标表供引用（目录与工程脚本之间的桥接只允许目录访问器本身）。`gradle.properties` 版本声明段中的每一个键 MUST 有真实取用点（插件声明语句或 BOM 导入语句），全仓零取用点的键 MUST NOT 保留；版本目录与集中托管声明中的每一个条目 MUST 有真实消费方，消费方既包括工程脚本的具名引用，也包括该条目在解析图中对传递坐标的实际钉扎，两者皆无的条目 MUST NOT 保留。同一版本族在事实源与各类托管源之间的具名声明 MUST 唯一：事实源声明什么版本，解析生效的版本就 MUST 是什么版本，二者不一致的状态 MUST NOT 存在（生效与声明的对账行为见"托管版本面在配置期与声明事实源对账"需求）。

#### Scenario: 升级版本只改事实源一处
- **WHEN** 维护者把某大头版本从当前值升到新值，仅修改 `gradle.properties` 对应行，或仅修改版本目录中对应条目的版本字段
- **THEN** 全仓模块经具名引用自动取得新版本，无需改动任何模块构建文件，也不存在第二个需要跟改的版本声明点

#### Scenario: 模块内手写坐标版本被判违例
- **WHEN** 某模块构建文件写出携带版本号字面量的完整坐标字符串（绕过版本目录）
- **THEN** 评审判定违例，要求把该坐标收入版本目录后以具名访问器替换，杜绝同一依赖两处版本漂移

#### Scenario: 私设第二引用表被判违例
- **WHEN** 某变更在任一脚本里重新以 ext 映射建立坐标表或版本表，替代或旁路版本目录
- **THEN** 判定违例：目录之外的具名引用表使访问器的来源失去唯一性，要求删除该表并回到目录声明

#### Scenario: 零取用点的版本键被判违例
- **WHEN** `gradle.properties` 版本声明段中的某个键，在插件声明语句、BOM 导入语句与动态属性读取三类取用形态下均无任何引用点
- **THEN** 评审判定违例，要求删除该键，或补上真实取用点并使其通过配置期对账；同族版本在另一事实源已有具名声明时，删除死键即是恢复单一事实源

#### Scenario: 无落点的托管条目被判违例
- **WHEN** 版本目录某条目既没有任何工程脚本引用，经解析树核对也不钉扎任何实际进入解析图的传递坐标
- **THEN** 评审判定违例，要求连同集中托管声明与目录条目一并移除；有传递落点的条目 MUST 在声明处注释登记其所钉扎的传递坐标，作为消费方身份的说明

## ADDED Requirements

### Requirement: 托管版本面在配置期与声明事实源对账
构建系统 SHALL 在任意构建的配置阶段核对事实源具名声明的大头版本族（日志族、网络传输族、序列化族、容器测试框架族、监控与注册中心客户端族等凡在 `gradle.properties` 具名声明的版本键所辖、且成员版本与所属 BOM 版本同值的坐标族）的实际生效托管版本；任一族的生效版本与声明版本不一致时，构建 MUST 以配置失败中止，并逐项列出失配的坐标、声明值与实际生效值。任何影响多源托管优先次序的声明写法调整 MUST NOT 在不使该对账失败的情况下改变某族的实际生效版本。

#### Scenario: 声明与生效一致时对账通过
- **WHEN** 维护者执行任意一次构建，各托管族的实际生效版本与 `gradle.properties` 及版本目录的声明值逐族一致
- **THEN** 对账静默通过，配置与解析正常进行，构建不因此增加可见输出

#### Scenario: 次序遮蔽导致生效偏离声明时配置失败
- **WHEN** 某次调整后，一个在事实源声明了版本的坐标族被另一托管源以更晚生效的次序覆盖，实际生效版本与声明值不再一致
- **THEN** 构建在配置阶段失败，错误输出逐项列出该族的坐标、事实源声明值与实际生效值，维护者修正次序或声明后再次构建才恢复通过
