# 历史发布清单三方对账记录（任务 1.1）

对账时间：2026-10-02。证据来源三方：制品库 maven-releases 浏览清单（匿名 REST，代表工件 `tny-game-bom`、`tny-game-common-lang`、`tny-game-net`、`com.tny.game.gradle.plugin` 的并集）、`git tag` 账本（21 条 `*-RELEASE`）、`*.release` 分支（`4.1.0.release`、`5.5.0.release`）。

## 结论

1. 制品库现存正式发布版本共 7 个：`3.2.0-RELEASE`、`3.2.1-RELEASE`、`3.2.2-RELEASE`、`3.3.0-RELEASE`、`3.4.1-RELEASE`、`4.1.0-RELEASE`、`5.5.0-RELEASE`。其中 `4.1.0` 与 `5.5.0` 证实确实发布过（与发布分支互为佐证），补上了 tag 断代的两个世代。
2. git 标签账本含 21 个发布号，其中 14 个在制品库中已不存在（2.x 世代全部、`3.0.0`、`3.0.1`、`3.1.0`、`3.4.0`）。差异方向为"有标签、无制品"，最合理解释是制品库经历过服务器重建而早期构件未迁移；标签与旧分支是这些发布曾存在的独立证据。
3. 黑名单取两侧并集、共 23 个裸号收录进 `gradle/released-legacy.txt`。依据：黑名单的语义是禁止同号复用，多收仅约束复用自由（保守安全），漏收才会造成两种形态同号共存导致排序纠缠。四段号 `2.0.2.1` 至 `2.0.2.4` 一并收录，虽然新形态（三段号）不可能与其撞号，列出可保持账本完整。
4. 未发现"已发布但 git 无任何记录"的条目，即无需要阻断结论的未解释风险。

## 证据局限声明

制品库核对基于四个代表工件的浏览清单；理论上若存在"只发布过某冷门工件的某版本"的极端情形会被漏掉，但发布体系按分支整体发全部模块（`build.gradle` 对全部子模块统一设 version），冷门工件单独跳版的可能性与分支、标签、代表工件三方证据互斥，判定为可忽略。
