# net-protocol Specification (Delta)

## ADDED Requirements

### Requirement: 键控认证代次的报文校验码与键流连续性
报文编解码 SHALL 提供"键控认证代次"作为校验/加密算法的可装配代次：启用该代次后，校验码 MUST 为以连接密钥材料为输入、绑定包号与载荷全文的键控消息认证码截断值，其长度与现有校验码字段（8 字节）相同，帧字节布局 MUST 不变；任何不能复算该键控函数的对端（包括持有既有无键校验算法的端）构造的改包 MUST 在校验步骤被拒绝。同一代次内的混淆键流输出 MUST 与既有混淆实现，在相同密钥材料与包号下逐字节等价。未启用该代次的部署 MUST 保持现行为逐字节不变。

#### Scenario: 认证代次报文正常收发
- **WHEN** 链路两端均配置启用键控认证代次，发送一条启用校验与混淆的报文
- **THEN** 接收端校验通过、载荷完整还原；线上帧的字段布局、校验码长度与旧代次报文完全相同

#### Scenario: 改包无法伪造校验码
- **WHEN** 一方在密文载荷中篡改任意 1 字节后送达对端（对端启用认证代次）
- **THEN** 键控校验重算不匹配，该报文按既有"校验不通过终止该连接处理"的契约拒绝，不因混淆可逆而放行

#### Scenario: 换皮重放被包号绑定拦截
- **WHEN** 攻击者将捕获报文的载荷原样保留、改写为新包号并同步重算无键校验码后送达
- **THEN** 因键控校验码与包号绑定，重算不匹配，报文被拒（既有严格单调包号检查之外的第二道拦截）

#### Scenario: 键流逐字节等价（密文语义连续）
- **WHEN** 相同连接密钥材料、相同包号、相同明文，分别经既有混淆实现与认证代次的混淆实现变换
- **THEN** 两者输出的线上字节逐字节相同（对端无需感知混淆实现换代）

#### Scenario: 未启用代次的部署零影响（向后兼容锚）
- **WHEN** 部署未将校验/加密装配切换至认证代次（默认状态）
- **THEN** 报文编解码全部行为与变更前逐字节一致，旧版本对端互通不受任何影响

#### Scenario: 混布期对端不匹配的可观测拒绝
- **WHEN** 仅单端切换认证代次，其发出的代次校验码送达仍按旧算法重算的对端
- **THEN** 对端按既有校验失败路径拒绝该报文（可诊断、不静默误解密），部署文档声明两端必须同批切换
