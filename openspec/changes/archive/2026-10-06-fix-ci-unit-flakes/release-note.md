# Release Note（fix-ci-unit-flakes）

- **变更内容（设施向，无新增公共 API 与协议改动）**：unit 工作任务装上与 integration 工作任务同款的
  诊断三件套——捕获步 `continue-on-error` 加 `tee`、失败时把案卷投递到孤儿分支 `ci-unit-diag`、末尾
  显式 `exit 1` 保持硬门禁。电路先经一次性探针自证：探针轮（run#35）计划内红、案卷五件齐投递，
  随后探针回滚；负半程"绿时不投递"由 run#39 分支尖端不变实证。
- **根治内容与案卷编号**：两个自然红案卷都定罪为"时序与并发观测断言在 CI 负载下翻转"家族——
  案 #1（run#38）：`drama.task` 测试族的 `TypeStageTest` 与 `VoidTypeStageTest` 把墙钟窗口判据改为
  尝试计数判据，`FlowTestUnits` 驱动循环加十秒绝对上限，两个测试类加类级超时兜底；
  案 #2（GitHub Actions run id 37165077819）：`ObjectLockerTest` 把固定睡眠持有改为会合形态，
  `CollectionLockTest`（本地登记 #2/3/4 点名的用例）把单次并行驻留观测改为二十秒有界窗口内多轮重试；
  同轮修复生产侧 `MapperLocker` 获取失败与中断四条路径"归还引用计数却不销毁条目"的残留
  （提交 82b71062）。本册唯一的实施期范围追加是该生产模块改动，提案工件已按修订注记对齐实际。
  根治提交：82b71062（生产）、43118456 与 36b96fde（测试），均已入库 5.7.x 线。
- **门禁语义**：零变化。unit 仍是硬门禁——没有引入测试重试、没有降级、没有新增排除模块；
  诊断电路只做失败案卷的只读采集。
- **下游影响**：无坐标变化、无接口变化。依赖 `5.7.x-SNAPSHOT` 的下游可观察到的唯一差异是
  `MapperLocker` 内部映射表的 `size()` 归零观测从"取决于最后释放者身份"变为确定收敛，
  不构成任何破坏点；消费模块 tny-game-data 与 tny-game-net 的测试已在本地空载、CPU 烧机负载
  与 CI 三环境下全绿。
- **收口与续账**：验收判据为"根治提交后连续十次推送 unit 零红"（任务 4.2），计数登记在本变更
  `diagnosis.md` 的观察账，新口径自修复落地后的首个全绿轮 run#100 起算。证据账如实声明一处损耗：
  案 #1 轮（run#38）的案卷抢救失败——固化四件在入库时即为空文件，原件已被分支强推覆盖，
  该案的签名证据现仅存定罪栏正文摘录；协议同轮补齐了"转存后逐一验非空"的执行（案 #2 与复发轮
  两轮五件均已完整固化于 `natural-red-2/` 与 `natural-red-3/`）。
