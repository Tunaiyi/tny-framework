# net-protocol Specification (Delta)

## ADDED Requirements

### Requirement: 载荷加密的全窗口覆盖与相对键流相位
对声明加密位的报文，发送方 MUST 对载荷的**每一个字节**施加键流变换；键流的取位 MUST 以载荷窗口内的相对位置计算，MUST NOT 依赖载荷缓冲在内存池中的绝对位置。接收方以同一规则还原后，载荷内容 MUST 与发送方原始内容逐字节一致，且 MUST NOT 因收发两端缓冲池位置不同而产生差异。

#### Scenario: 启用加密的报文全载荷被变换
- **WHEN** 服务端以启用加密的配置编码一条载荷长度为 N 的报文，且其载荷缓冲取自内存池、窗口起点非零
- **THEN** 线上帧内载荷的 N 个字节全部经过键流变换（不存在任何明文段），且接收方按契约可完整还原

#### Scenario: 键流相位与缓冲池位置无关
- **WHEN** 同一条报文分别在窗口起点为 0 与非 0 的两种载荷缓冲上编码
- **THEN** 两次产生的线上载荷字节完全相同

#### Scenario: 新旧两端同批升级后往返一致
- **WHEN** 收发两端均为修复后版本，任一端缓冲池位置漂移（分配复用导致窗口起点变化）
- **THEN** 加密报文的编码→传输→解码往返结果与窗口起点为 0 时的历史行为逐字节一致，校验通过

#### Scenario: 未声明加密位的报文行为不变（向后兼容锚点）
- **WHEN** 报文未声明加密位（现有未启用加密的部署）
- **THEN** 其编解码行为与修复前逐字节一致，旧版本对端无需升级即可互通

#### Scenario: 窗口起点为零的历史语义保持
- **WHEN** 载荷缓冲窗口起点恰为 0（如未池化分配）
- **THEN** 修复后的键流变换结果与修复前逐字节一致（该场景下两者定义重合）
