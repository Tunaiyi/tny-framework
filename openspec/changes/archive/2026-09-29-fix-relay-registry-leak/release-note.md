# RELEASE NOTE（tny-game-net · fix-relay-registry-leak）

## 修复：中继注册表两类条目滞留

- **链路条目**：物理断线（主路径，占绝大多数）与主动关闭均即时摘除——经 `onDisconnect`
  单钩子覆盖（close 内部必经 disconnect）；值相等 CAS 防误摘。网关扩缩容/网络抖动频繁的
  长服，linkMap 规模从"单调增长"收敛至活链路数。
- **隧道条目**：协议显式关闭改为 remove-取回-即关，重复关闭天然幂等（CHM 唯一胜者）。
  该修复位于 `BaseRelayExplorer` 父类，服务端与客户端 explorer 同时受益。

## 重要语义澄清（防未来过度清理）

链路断开时其**隧道条目必须保留**——这是网关重连后隧道恢复（re-CONNECT 置换 / 显式切换
重绑两条协议路径）的前提，已由规格与路障测试④固化。请勿把它当泄漏"顺手清理"。

## 登记边界（不在本变更处理）

客户端"放弃隧道但未发协议关闭"时条目仍滞留：属异常运维路径，量级与"每次断线必留"的
链路泄漏不同；其清理需要超时/保留策略设计，须以真实流量数据定策，留待专项评估。
