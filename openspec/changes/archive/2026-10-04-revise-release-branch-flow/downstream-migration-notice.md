# 5.4 下游迁移说明（草稿；投递时机=首个次版本线开线后随发布通知，投递前需用户确认）

致：锁定 TnyFramework 滚动快照坐标的下游业务工程。

**发生了什么**：自变更 `revise-release-branch-flow`（openspec）生效起，分支模型定形为三层：
`main` 是特性开发的唯一顶点，`5.7.x` 这类版本线成为"特性冻结线"，`5.7.9.release` 容器加
标签 `v5.7.9` 是不可移动的发布层。契约影响一条：**滚动快照坐标的内容口径收窄**。

**对依赖声明的影响**：无。`5.7.x-SNAPSHOT` 坐标字符串不变，既有依赖声明无需任何修改；
它今后每晚提供的是"5.7 系列的最新维护态"——只含修复，不再含新特性。补丁版本（5.7.9、
5.7.10……）将始终只做修复，可以按 semver 的补丁语义信任它们。

**想要持续获得新特性的下游**：请在下一个次版本线（5.8.x）开线后将坐标切换到
`5.8.x-SNAPSHOT`；开线当晚该坐标即由夜间构建生效。特性今后只随次版本到达，
首个此类发布是 5.8.0。

**历史事实不变**：5.7.8 及其之前的发布按旧语义执行，其内容与标签存证维持原样；
每个已发布版本"出自哪个提交"依旧可用 `git ls-remote` 查标签 `vN.M.K` 的解引用记录回答。
