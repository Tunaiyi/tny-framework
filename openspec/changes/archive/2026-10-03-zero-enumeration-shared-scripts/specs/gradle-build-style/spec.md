# gradle-build-style Spec Delta

## ADDED Requirements

### Requirement: 共享构建脚本禁止枚举具体工程名
根构建文件与 buildSrc 约定插件脚本（合称共享构建脚本）的代码 MUST NOT 出现具体工程的名字字面量或以其为参数的跨工程引用；工程属于哪条装配线、参与哪项对账与聚合，MUST 由两类可验收通道判定：命名约定（前缀/后缀谓词，约定的权威定义记录在 settings.gradle 的模块清单注释中）或自报登记（工程通过应用标记插件把自己登记进根工程清单，供跨工程合同消费）。本需求的验收基准："新增一个归入既有类别的模块，共享构建脚本零改动"。注释与文档中为交代来由而出现的完整工程名不受本条限制（文字规则反而要求给出全名）；模块自己的构建文件引用兄弟工程属模块声明面，不在禁列。

#### Scenario: 新增类别成员零改动自动归类
- **WHEN** 仓库新增一个名字以 -integration-test 结尾的集成测试模块，settings.gradle 加 include、模块文件声明自身，未改动任何共享脚本
- **THEN** 该模块自动从 java 发布线排除、自动被 BOM 约束面排除、组号按发布组派生，全量构建与既有合同检查全部如常通过

#### Scenario: 共享脚本写死精确名被判违例
- **WHEN** 评审发现某变更在共享脚本里以精确工程名增减成员或处理例外（形如名字等于判断、project 冒号路径引用）
- **THEN** 评审判定违例，要求改为命名约定判定或自报登记；无法模式化的个体属性（如不发布设施）必须走登记通道而非点名

#### Scenario: 登记合同对未登记工程不误伤
- **WHEN** 一个工程未应用不发布标记插件，另有一个发布模块正常依赖它
- **THEN** 零发布对账通过；一旦有工程发布依赖指向登记在册的不发布工程，配置期报红并列出依赖双方路径
