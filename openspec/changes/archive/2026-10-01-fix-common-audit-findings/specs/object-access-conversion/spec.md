# object-access-conversion Specification (Delta)

## Purpose
本能力收口框架内两处横切基础设施的行为契约：其一是方法"属性形态"的判定规则——以反射驱动的配置与报文属性装配等机制，依据方法的命名前缀与签名形状判定其是否为取值形态、赋值形态，判定一旦颠倒属性识别即完全错误；其二是叠加于字典之上的包装键值访问器（配置/报文键值视图）的类型化读取语义——条目数、缺键默认值、含键名的受控空指针与错型值的宽松转换必须对消费方可观察、可预期，并与直接持有字典的非包装访问器保持同一转换结果，使同一份键值数据经任一访问路径取值得到一致行为。

## ADDED Requirements

### Requirement: 方法属性形态的判定规则
系统 MUST 仅在方法同时满足"无参数、返回值非 void、名称以 get 起始"时，或同时满足"无参数、名称以 is 起始且返回布尔类型"时，将其判定为取值形态。名称以 set 起始且恰有一个参数的方法 MUST 被判定为赋值形态。带参数的 get/is 前缀方法、无返回值的 get 前缀方法、以及不具有上述前缀形态的普通方法 MUST NOT 被判定为取值形态。属性形态的判定 MUST 等价于"属于取值形态或属于赋值形态"两者之一。

#### Scenario: 规范存取方法判定正确
- **WHEN** 对一个含"无参且返回字符串的 get 前缀方法"、"无参且返回布尔的 is 前缀方法"、"单参 set 前缀方法"的普通对象形态分别执行三项判定
- **THEN** 前两者被判定为取值形态（且为属性形态），第三者被判定为赋值形态（且为属性形态）（BREAKING：原取值判定误用赋值判定，结果完全颠倒）

#### Scenario: 赋值形态不被误判为取值形态
- **WHEN** 一个名称以 set 起始、恰有一个参数的方法参与取值形态判定
- **THEN** 该方法不被判定为取值形态

#### Scenario: 带参或无返回值的 get 前缀方法不是取值形态
- **WHEN** 两个 get 前缀方法参与形态判定：一个带参数，一个无返回值（void）
- **THEN** 二者均不被判定为取值形态，也不被判定为属性形态

#### Scenario: 普通方法三形态均不命中
- **WHEN** 一个有返回值但名称以 get/is/set 之外的词起始的无参方法参与形态判定
- **THEN** 它不被判定为取值形态、赋值形态或属性形态

### Requirement: 包装键值视图的条目数与缺键语义
包装键值访问器对外报告的条目数 MUST 等于其底层字典的实际条目数（BREAKING：原实现恒返回 0）。按键取值时：存在缺省入口且键不存在（或对应值为空），MUST 返回缺省值；不存在缺省入口且键缺失，MUST 抛出消息中含键名的空指针异常，使调用方可直接定位缺失项。

#### Scenario: 视图条目数反映底层实际数量
- **WHEN** 向包装视图的底层字典放入 N 个条目后读取该视图报告的条目数
- **THEN** 条目数等于 N，不恒为 0

#### Scenario: 缺键返回缺省值
- **WHEN** 通过带缺省值的取键入口读取一个不存在的键
- **THEN** 返回调用方给出的缺省值，不抛出异常

#### Scenario: 无缺省入口缺键抛含键名空指针
- **WHEN** 通过无缺省值的必存在取键入口读取一个不存在的键
- **THEN** 抛出空指针异常且异常消息包含该键名，不返回 null 掩盖缺失

### Requirement: 类型命中直取与浮点取值正常返回
包装键值视图的类型化取值入口在存储值已与目标类型一致时 MUST 直接返回该值，此正确类型路径的行为与开销 MUST NOT 因转换语义引入而增加。以浮点类型读取底层实际为浮点数的存储值 MUST 正常返回（BREAKING：原实现以基本类型描述符探测恒不命中，值存在时必抛类型转换异常）。

#### Scenario: 类型命中直接返回
- **WHEN** 以某类型化入口读取一个存储值类型恰为该目标类型的键
- **THEN** 直接返回该存储值，结果与存入值相等

#### Scenario: 浮点值正常读取
- **WHEN** 底层存储值为浮点数，分别经带缺省值与无缺省值的浮点读取入口读取该键
- **THEN** 两次均正常返回该浮点值，不抛出类型转换异常

### Requirement: 错型值的宽松转换与非包装访问器统一
本项为本变更待实施内容：包装键值视图对类型不匹配存储值的转换语义 MUST 与直接持有字典的非包装访问器统一——存储值为数字文本时 MUST 转换为目标数值类型的对应值；存储值为其它数值类型时 MUST 按数值跨类型窄化为目标类型；目标类型为枚举时 MUST 按枚举名称从文本匹配取值。转换失败 MUST 抛出类型转换或参数类异常并指明失败原因，MUST NOT 静默返回 null 或缺省值伪装成功；正确类型路径的行为与开销保持不变。

#### Scenario: 数字文本转换为对应数值
- **WHEN** 存储值为数字文本（如 "123"）的键被以整数类型读取
- **THEN** 返回对应的数值 123，与非包装访问器读取同一数据的转换结果一致

#### Scenario: 数值跨类型窄化与枚举按名取值
- **WHEN** 存储值为一数值类型而读取目标为另一数值类型，或存储值为枚举名称文本而读取目标为该枚举类型
- **THEN** 前者返回窄化后的目标数值，后者返回按名称匹配的枚举值

#### Scenario: 转换失败显式抛错
- **WHEN** 存储值为无法解释为目标类型的文本（如非数字字符串）的键被以数值类型读取
- **THEN** 抛出类型转换或参数类异常且消息指明转换失败，调用方不会拿到被伪装的缺省结果

#### Scenario: 正确类型路径不受转换统一影响
- **WHEN** 存储值类型与读取目标类型一致的键经类型化入口读取
- **THEN** 直接返回原值，行为与开销同转换统一之前一致
