# Design

## Context

六个基础设施模块（common-digest/io/lang/lifecycle/reflect/scheduler）全量深度审计的结论：约 60 项确认缺陷，模式统一为"静默失效优先于显式失败"。规格差量已按 9 个能力域立约（见 specs/）。**当前工作区状态**：审计会话已将其中大部分修复与约 20 个回归测试类落地（未提交），六模块单测、全仓编译与下游 net/protoex 测试通过；本设计文档同时覆盖"已实施修复的决策留痕"与"两项待实施收尾"（D1、D2）。

爆炸半径核查（codegraph + 全仓 grep 双轨，索引以工作区为准）：

| 关键符号 | 直接调用面 | 风险 |
|---|---|---|
| Map 包装访问器（asObject/asNotNullObject） | 仅经门面 `MapAccessors.wrap/cast` 暴露；仓内活跃调用 2 处（接入节点信息、中继服务实例），低频配置读 | 低 |
| 生命周期注册表辅助（putIfAbsentLifecycle） | 包私有，三个同构 value() 调用点 | 低 |
| 串行 worker 环（loop/resumeLoop） | **每会话命令热路径**（net 的串行命令执行器）+ 既有嵌套编排测试 | 高（本变更最高风险点） |
| 配置热更/词表加载 | starter 词过滤自动配置（聊天审核热路径判定底座）、basics 模型加载 | 中高 |
| AttrKeys 键创建 | net 属性键定义与 starter 切面/插件混用两种键风格 | 中 |
| 调度队列/触发器/trigger | starter-basics 定时任务装配、任务接收器、备份恢复 | 中 |
| 字节编解码（小端/键流窗口） | net 校验码与载荷加密（每包路径） | 中（语义不变，仅钉死与修边） |
| RSA/对称密码/Base62 | 全仓零外部调用点（对外发布 API） | 低（兼容性见下文） |

## Goals / Non-Goals

**Goals**：把 9 个能力域的已确认错误行为收口为规格承诺；修复全部高置信缺陷；并发/热路径行为以确定性测试钉死；补齐 D1 转换统一与 D2 调用点清理。
**Non-Goals**：不修休眠地雷族（Frequency/SwitchQueue/DelayCommand 族、SnowflakeIdCreator 回拨、MathAide 权重族、LockAide/ObjectLockHolder 链、reflect 缓存键 B2/B3/B4/B5、XStream 反序列化面）——已由遗留清单记忆与后续独立变更承接；不引入 module-info；不改任何报文格式。

## Decisions

### D1 Map 包装访问器：热点直取 + 宽松转换统一
错型值先走类型命中直取，未命中再走宽松转换（数字字符串→数值、数值跨类型窄化、枚举按名），失败仍抛类型/参数异常——与非包装访问器语义对齐。
**依据**：P6（同一访问契约的两个实现行为分裂，实现必须守约不打折）；P13（快路径成本不变：1 次 isInstance + 读值，零分配；宽松路径仅在原必抛场景启用，无新增热路径开销）。
**否决**：a) 维持严格 cast——P6 分裂继续存在，调用方踩坑后自行写解析更慢且行为各异；b) 全量改走 convertTo——正确类型路径多付包装类查表与 Number 分派成本（P13：热路径量化）。
**兼容性**：BREAKING（错型输入由必抛变为尝试转换）；调用面仅 2 处低频读，均在"值即目标类型"路径，行为不变。测试先行（见 tasks）。

### D2 注册表辅助泛型化收尾
`putIfAbsentLifecycle` 定义已泛型化（`<I extends Lifecycle<?, ?>> I putIfAbsentLifecycle(Class<I>, I)`）；本变更删除 PostStarter/PrepareStarter 两个调用点残留的冗余强制转型（PostCloser 已无转型可作对照），三处形态一致。
**依据**：P11（包私有辅助不入合同，无兼容约束）；P13（可验证性：新增阶段类无需复制 unchecked 转型）。

### D3 串行 worker 唤醒策略：归属校验 + 队列非空兜底（本变更最微妙决策）
环挂在 `waitingInner`（volatile 发布）上做**身份归属校验**：仅"当前等待的那个内层"完成可唤醒；但归属失配时若**队列非空**仍唤醒。
**依据**：P4（不变量"至多一个在飞任务"由归属校验保护——异己迟到完成不得把还在等待新任务的环提前唤走）；P6（既有嵌套编排形态——父任务内层依赖排队子任务——必须继续不死锁，是契约可用性而非实现细节）；模式卷决策表"引用整体替换 → volatile 快照读"用于 waitingInner 发布；CAS 状态机零额外锁（P13）。
**否决**：a) 维持旧"任何内层完成无条件唤醒"——正是误唤醒破坏串行序的根源（迟到完成 + 队列非空的组合仍可能并发两任务，实测可复现）；b) 严格仅归属唤醒——嵌套链（父等子、子排队、无人唤醒）确定死锁，既有测试当场挂住（前次会话实证）；c) 超时任务出队即物理移除——`ConcurrentLinkedQueue` 无 O(1) 中间摘除，且与"跳过执行"语义等效而代价更高。
**残留风险**：误唤醒窗口收窄但未归零（"异己完成 + 恰有积压"时下一任务与迟到父任务并存）——该窗口正是嵌套链的存活通道，属有意取舍，写入 Risks。

### D4 超时双向收口：活性 + 副作用边界
两条互补规则：排队任务轮到时外层已完成（超时）→ 跳过执行（副作用不再后置于调用方脱身）；外层经定时器超时 → afterTimeout 钩子唤醒挂在其内层上的环（调用方脱身后队列必须继续）。
**依据**：P4（"调用方已超时脱身的任务不得再产生副作用"与"环不得永久停摆"是同一状态机的两条不变量）；P11（行为变更标 BREAKING：原实现超时的任务照常执行）。

### D5 io 失败方向：热更 fail-safe 保留，首载 fail-fast 上抛
读取失败（IO 异常/流不可用）时：热更路径保留在役配置/旧词表并告警；首载路径显式抛异常，禁止空表"成功"启动。reload 通知逐监听器 try/catch 隔离；共享表引用 volatile 化、监听集合并发化、输入流基类统一关闭；注销监听器修正为真移除（原误写为追加）。
**依据**：P12（方向变更先入规格：config-loading/word-filtering 各含双路径 Scenario）；模式卷"volatile 快照读，零锁"先例（配置整体替换语义，读侧零锁）；P11（BREAKING：原 fail-open 清空为事故源，新行为对下游是修复而非破坏，迁移成本≈0）。
**否决**：热更失败也上抛吞掉——监听发生在轮询线程，抛出会终止 observer，反而丢后续热更（P4 不变量优先）。

### D6 调度器修复面
互斥锁读锁笔误→写锁；执行池 static→实例字段（volatile，reload/shutdown 只动本实例）；队列 maxSize≤0 驱逐守卫、同刻任务处理器合并（不再整批静默丢）、restore 方向改保留最新；触发器比较器 Long.compare + 实例序号定序——序号保证"同刻不同实例互不相等"，维持跳表不丢任务的既有语义，仅补全序性（原相等返回 -1 违反 Comparable 契约）；无未来触发点 cron 显式失败 + 方案级 try/catch 隔离；挂起/延长时间全程 long（消 32 位截断）；stop 清理挂起态；lengthen 成功返回真。
**依据**：P4（队列/触发器各守自身不变量：有序、不丢、方向一致）；P6（lengthen 恒假是实现打折）；模式卷"短临界区互斥"（ReentrantReadWriteLock 修正即回归既有选型，非另起炉灶——M1）。
**否决**：同刻重复任务直接丢弃——丢失面是整批处理器且无痕迹（P12 不可验证）；恢复保留最旧——与入队驱逐最旧方向自相矛盾（P4 不变量冲突）。

### D7 digest 修复面
字节短窗读取补齐 7 字节档位、无符号解析掩码收窄 0~FF；键流窗口全窗覆盖+相对相位（与 net-protocol 既有契约引用对齐，不改语义）；Base62 静态缓冲→调用局部（单线程逐字结果不变）；密码 String 通道编/解两侧统一 UTF-8；RSA 分段块大小从密钥模数推导（不依赖 provider 推算）+ 密钥工厂逐次创建（JCA 实例非线程安全）。
**依据**：P4（往返无损是编解码不变量）；P11（掩码域收窄、受检异常签名扩展、UTF-8 固定均标 BREAKING；核查全仓零活跃调用点，迁移说明入版本公告）；模式卷"第三方体系错误语义翻译"（cron 无未来触发点由裸 NPE 翻译为受控异常）。

### D8 AttrKeys：全名单表 + computeIfAbsent
查询与写入统一按全名，`ConcurrentHashMap.computeIfAbsent` 原子建键。同 (命名空间,名) 恒等；跨命名空间隔离（消除短名劫持与双实例）；同名字空间并存时聚合视图显式冲突（维持现状钉桩）。
**依据**：模式卷决策表"短临界区互斥——原子替换"（computeIfAbsent 即先例形状，M1）；P4（"一键一实例"不变量）；P11（BREAKING：原被劫持合并的键将分离——仓内混用两种键风格的调用点核查后行为只变得更正确）。

### D9 EmptyImmutable 三族首写：沿用仓内 Map 已修复先例
List/Set 补齐与 Map 完全相同的双检锁换表模式（注释同款说明）。生产路径（事件通知器、服务发现监听、奖励模型字段）creator 提供并发安全容器时写侧安全；默认容器维持 ArrayList/HashSet 非并发语义（契约：并发写需自带并发容器）。
**依据**：M1 先例优先（同族 Map 的修复注释即仓内活先例，List/Set 未同步修复是遗漏而非另案）；P6（同族行为一致）。

### D10 链式缓冲窗口语义
节点窗口写返回值=length；三参追加等价单参追加（内容起点正确——JDK `wrap(buf,index,len)` 以 index 为 position 而非 arrayOffset，零拷贝节点表示法无法承载非零偏移，故三参追加委托窗口写入）；扩容复利；release 复位 size。
**依据**：P4（size==累计写入字节数是不变量，污染序列化长度前缀为 P11 报文兼容级缺陷）；P13（委托路径为复制一次，追加调用面在 protoex 为单参形态，热路径无新增成本）。

### D11 IDE「not exported」告警：验证收口，不改代码
实证链：涉事接口本为 public；全仓无 module-info；jar 仅 Automatic-Module-Name（自动模块导出全部包）；javac 全量编译+六模块测试通过。根因为 IDEA 工程模型失同步（modules.xml 仅注册 10 个模块，该模块未被导入，符号解析落到 mavenLocal 快照 jar）。处置：验证任务确认"公共签名不引用不可访问类型" + Gradle re-sync 指引，零代码改动。
**否决**：添加 module-info——P10（无 JPMS 模块路径消费者证据）；P11（模块描述符即新合同面，导出裁决需全量梳理）。

### D12 测试策略（对应 P12/P13）
已落地约 20 个测试类构成回归底座（工作区，六模块全绿）；D1 补"转换矩阵"测试且**先于**实现落红；并发用例统一栅栏 + 有界等待 + 原子计数（禁 sleep 判定、禁无超时 join）；调度时间类用例固定基准时刻 + 显式传入检查时刻。

## Risks / Trade-offs

- **D3 误唤醒窗口残留**（最高风险）：极端交错下（异己迟到完成 + 队列恰有积压）可短暂并发两任务——嵌套链存活的必要代价；缓解：归属校验把窗口从"任何完成"收窄到该组合；串行序测试（maxConcurrency==1）作为哨兵。
- **每会话热路径行为变更**（D4 超时跳过执行）：下游若存在"超时后仍指望任务执行产生副作用"的用法将感知变化——审计未发现此类调用形态；发版公告单列。
- **调度恢复数据方向改变**（D6 restore 取最新）：旧备份在新版本下恢复的任务集合不同（更正确）；运维侧需知悉。
- **BREAKING 面广而深窄**：十余项行为收窄/修正，多数调用点为零或必错路径；集中风险在 D1/D5/D8 的"原可跑通路径变行为"——全部经全仓调用点核查。
- **mavenLocal 陈旧快照**可能持续干扰 IDE 符号解析：建议验证任务中确认后由用户决定清理（不在变更内动 ~/.m2）。

## Migration Plan

分批合入：① 工作区已落地修复 + 测试（低风险行为修正群）→ 六模块 test + 全仓编译门禁；② D2 调用点清理（纯形态）；③ D1 转换统一（测试先行，红→绿）；④ 发版说明汇总 BREAKING 清单（无报文格式变更，客户端无需升级；下游按公告核对错型配置读取与超时副作用依赖）。归档前跑 `/opsx:verify`。
