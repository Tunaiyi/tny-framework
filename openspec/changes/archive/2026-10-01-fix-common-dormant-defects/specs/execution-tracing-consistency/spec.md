# execution-tracing-consistency Spec Delta

## Purpose

为框架的运行跟踪观测面（加载耗时监控类路径）立约：同一观测目标在「开始→结束→再开始」的正常周期重入下不得产生误报与登记泄漏，跟踪起止两侧的日志时间必须单位一致、基准如实声明，耗时统计口径真实可换算。该观测面被模型加载与协议模式加载的启动耗时统计实际消费，误报与单位错乱会直接污染运维日志与耗时指标。

## ADDED Requirements

### Requirement: 同目标跟踪周期重入不误报且条目随结束回收
对同一观测目标执行「开始跟踪→结束」完整周期后再次开始跟踪，MUST NOT 产生「任务没有结束」类误报告警（残留判定 MUST 并入"该目标的当前跟踪是否仍未结束"的完成态检查，而非仅凭登记存在即告警）；结束动作 MUST 使该目标在当次观测登记中被真实移除，使得下一周期的开始不携带上一周期的残留状态；未结束周期内的重入开始 MUST 仍给出真实告警（此时确实存在未闭合的跟踪）。

#### Scenario: 完整周期后重入开始零告警（正常路径）
- **GIVEN** 对某目标完成一次「开始跟踪→结束」
- **WHEN** 再对同一目标开始一次跟踪
- **THEN** 不产生任何「没有结束」告警，新跟踪独立开始，结束后可再次获取耗时统计

#### Scenario: 未闭合周期的重入开始仍如实告警（错误路径）
- **GIVEN** 对某目标已开始跟踪但尚未结束
- **WHEN** 再次对同一目标开始跟踪
- **THEN** 产生一条指示"存在未结束跟踪"的告警，且两次跟踪的登记状态可被查询接口如实反映（查询"是否跟踪中"在结束前后分别返回真/假）

#### Scenario: 结束动作真实回收登记（资源不泄漏）
- **GIVEN** 同一线程对多个不同目标分别开始跟踪
- **WHEN** 各目标逐一结束
- **THEN** 每次结束后可观测登记中不再包含该目标（无按键错配导致的残留），持续多轮「开始→结束」循环不使登记随目标数累积增长

### Requirement: 起止日志时间单位与基准声明一致
跟踪开始与结束两侧的日志时间戳 MUST 采用同一时间单位与同一时间基准换算；若计时源不是历元时钟，日志 MUST NOT 将其伪装为历元墙钟时间——要么换算为真实历元时间，要么明确标注为进程相对时长语义。耗时统计读数 MUST 与其命名单位一致且可由起止值直接推算。

#### Scenario: 结束日志时间戳与开始同单位同基准（正常路径）
- **GIVEN** 启用打印选项为「起止均打印」的一次跟踪
- **WHEN** 完成并开始各触发一次日志
- **THEN** 两条日志的时间字段量级一致（不因微秒/纳秒混算出现千倍偏差），且与耗时读数互相印证（结束时间-开始时间≈耗时）

#### Scenario: 未开始的跟踪结束读数显式化（错误路径）
- **GIVEN** 从未开始的跟踪对象
- **WHEN** 直接请求耗时统计
- **THEN** 得到显式的「未开始」指示（异常或明确的哨兵值语义），而非以缺省起点差值拼出天文数字

### Requirement: 观测登记与目标身份键一致
同一观测周期的登记、查询、结束、移除 MUST 使用同一目标身份作为键；跨线程的观测登记相互隔离（一线程的开始不影响另一线程对同目标的查询与告警）。

#### Scenario: 结束按登记时目标身份命中（正常路径）
- **GIVEN** 以某目标对象开始跟踪
- **WHEN** 以同一目标对象结束
- **THEN** 结束作用于该目标本应闭合的跟踪周期，返回的跟踪句柄即开始时登记的同一实例

#### Scenario: 未开始即结束的显式反馈（错误路径）
- **GIVEN** 某目标从未开始跟踪
- **WHEN** 直接请求结束
- **THEN** 产生「未开始」告警并返回可判空指示，调用方链式取耗时 MUST NOT 触发空指针（返回哨兵或显式异常，不得静默产出错误数值）
