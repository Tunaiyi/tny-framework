# Spec Delta: relay-link

## ADDED Requirements

### Requirement: 链路切换按隧道迁移语义处理
隧道从一条链路换绑到另一条链路后的迁移通知，接收方 MUST 按"隧道迁移"语义处理：该隧道已绑定的业务会话（认证状态、接入身份、属性）MUST 完整保留，MUST NOT 销毁重建；迁移通知 MUST NOT 把空参数解释为默认地址（0.0.0.0）。

#### Scenario: 故障转移后会话保留
- **WHEN** 原链路断开、隧道换绑到新链路并发出迁移通知
- **THEN** 接收端业务会话保持已认证状态与同一接入身份，玩家无感继续，无需重新登录

#### Scenario: 迁移通知类型自洽
- **WHEN** 触发链路切换
- **THEN** 对端收到的包类型字段语义为"切换"，接收端进入迁移处理分支而非连接建立分支

#### Scenario: 未成对升级期的兼容
- **WHEN** 尚未升级的旧侧仍按旧类型发送切换通知
- **THEN** 新侧按既有连接语义处置该包（维持旧行为），并记录可诊断的版本错配告警，不产生静默会话销毁

### Requirement: 中继载荷在早退路径终结释放
中继消息因链路已关闭、处理异常或编码异常而提前终止时，其载荷缓冲 MUST 恰好终结释放一次，被丢弃的消息 MUST 留痕可诊断（至少含链路与消息标识）；MUST NOT 把释放时点推迟给运行时的自动回收。

#### Scenario: 向已关闭链路写出即释放
- **WHEN** 业务向已关闭的链路提交中继
- **THEN** 载荷立即被释放且丢弃告警可定位；链路关闭流程不受影响

#### Scenario: 中继编码异常不泄漏不误发
- **WHEN** 中继包编码中途失败
- **THEN** 该包载荷恰好释放一次，且网络不出现半截帧（与编码零字节契约一致）

#### Scenario: 成功路径归属不变
- **WHEN** 中继被正常受理并完成转发
- **THEN** 载荷在转发完成时释放，无提前释放导致的悬垂读

### Requirement: 链路未识别的协议错误不被观测代码顶替
链路标识尚未建立时收到链路相关报文，系统 MUST 按协议错误规则处置该连接（按错误级别关闭），观测/日志环节 MUST NOT 以内部异常顶替这一判定，也 MUST NOT 退化为"仅记录不处置"。

#### Scenario: 未识别链路收到相关报文
- **WHEN** 尚未完成链路识别的连接收到链路相关报文
- **THEN** 连接按协议错误规则终止，日志可诊断根因

#### Scenario: 已识别链路的正常报文
- **WHEN** 链路识别完成后收到合法报文
- **THEN** 处理不受观测逻辑干扰，无额外失败面
