# Spec Delta: command-execution

## ADDED Requirements

### Requirement: 鉴权校验器可注册且按维度生效
协议维度与全局兜底的鉴权校验器 MUST 能在无既有同类注册时成功登记（登记动作本身不报错），且在请求鉴权时按"方法级 → 协议级 → 全局"的顺序解析使用；三级均缺失而该协议要求登录时，MUST 以未登录错误码拒绝。

#### Scenario: 全局兜底生效
- **WHEN** 某协议声明需登录、仅注册了全局校验器、请求携带合法凭证
- **THEN** 校验器被调用且请求放行

#### Scenario: 重复全局注册明确拒绝
- **WHEN** 第二个全局兜底校验器尝试注册
- **THEN** 注册被明确拒绝并给出可诊断错误，不出现内部空指针

#### Scenario: 方法级显式指定兼容既往
- **WHEN** 处理方法显式指定了校验器
- **THEN** 优先使用方法级校验器，行为与旧版本一致

### Requirement: 每个请求恰好收到一个终答
凡需要响应的请求，系统 MUST 保证最终送达且仅送达一个响应——包括处理中途抛出异常、中继目标不可用、结果缺失等一切失败路径；失败路径 MUST 以系统错误码应答，MUST NOT 让请求方只能等待超时，MUST NOT 重复应答或重复触发完成回调。

#### Scenario: 处理器异常仍回错误码
- **WHEN** 业务处理在写出结果前抛出异常
- **THEN** 请求方收到系统错误响应，服务端异常留痕

#### Scenario: 中继目标不可用仍回错误码
- **WHEN** 声明中继转发的请求其目标链路不可用
- **THEN** 请求方收到明确错误码而非静默

#### Scenario: 正常路径单次应答
- **WHEN** 业务正常完成
- **THEN** 响应恰好发送一次，完成监听恰好触发一次

### Requirement: 异步命令超时兜底不饿死会话
异步业务结果 MUST 具备可配置的兜底时限：超期未完成时系统 MUST 以错误码应答该请求并推进会话的串行执行队列；MUST NOT 允许一条永不完成的消息导致同会话后续消息排队饿死。

#### Scenario: 异步挂死被兜底
- **WHEN** 业务返回永不完成的异步结果
- **THEN** 兜底时限到达后该请求收到错误应答，下一条消息照常执行

#### Scenario: 正常完成不触发兜底
- **WHEN** 异步结果在时限内完成
- **THEN** 响应正常发出，无兜底介入痕迹

### Requirement: 未知模式报文安全吸收
未知或缺省模式的报文 MUST 被安全吸收：不入执行队列、不产生异常、至多一条可定位的告警日志；MUST NOT 影响同连接后续报文的处理。

#### Scenario: 回环类报文进入派发
- **WHEN** 一条派发层无对应处理的模式报文到达
- **THEN** 被丢弃并留一条告警，无异常堆栈刷屏

#### Scenario: 后续消息正常
- **WHEN** 未知模式报文之后收到正常请求
- **THEN** 正常请求按完整链路处理

### Requirement: 作用域过滤真实生效
协议按作用域（及部署类型）的过滤 MUST 用请求携带的对应维度与声明做真实比对：作用域不匹配的协议 MUST 按"协议不存在"处置，MUST NOT 因比对字段错位而恒放行或随机误拦。

#### Scenario: 作用域不匹配按不存在处置
- **WHEN** 请求作用于仅对另一作用域开启的协议
- **THEN** 返回与协议不存在一致的应答，业务方法未执行

#### Scenario: 匹配与未声明不受影响
- **WHEN** 作用域匹配或协议未声明作用域
- **THEN** 照常放行，与旧行为一致
