# Spec Delta: message-checking

## ADDED Requirements

### Requirement: 空可选值与缺省配置正确放行
可选参数取空值时，各取值类检查（长度、范围、格式、内容）MUST 放行且 MUST NOT 因内部异常拦截请求；超时检查阈值未声明或非正数时 MUST NOT 拦截（与既有超时语义一致），检查器 MUST NOT 因配置缺省抛出内部错误而返回系统错误。

#### Scenario: 空可选值通过取值检查
- **WHEN** 携带取值约束的可选参数为空
- **THEN** 检查放行，业务方法正常执行

#### Scenario: 非空违规仍被拦截
- **WHEN** 可选参数非空且违反范围或格式约束
- **THEN** 返回对应的参数错误码，业务方法未执行

#### Scenario: 缺省阈值不误杀
- **WHEN** 超时类检查器未配置阈值而协议流量到达
- **THEN** 报文不被拦截，不出现系统错误应答

### Requirement: 注解与检查器覆盖关系启动期校验
启动完成前，系统 MUST 校验参数校验注解与已登记检查器之间的覆盖关系：存在被业务使用的注解而无对应检查器时，MUST 以启动失败或明确的错误级日志使其可感知（选定：启动失败），MUST NOT 静默禁用该项校验。

#### Scenario: 缺失检查器启动可感知
- **WHEN** 某参数的校验注解没有对应的已登记检查器
- **THEN** 启动阶段报告失败并指明缺失项，不带着静默失效的校验上线

#### Scenario: 配置齐全正常启动
- **WHEN** 所有被使用的注解都有对应检查器
- **THEN** 启动正常，检查链行为与既往一致
