# Design

## Context

见 proposal.md - Why。技术事实基线（全部有案卷或本地复现支撑）：`gradle.properties:40` Netty 事实源现为 4.1.137.Final，`:48` gRPC 事实源 1.60.0；grpc-bom 经治理册导入并由八大头族对账守卫看护，`grpc-netty` 在依赖图中标记为 "selected by rule"，即版本键是全图唯一生效点。jetcd-core 0.7.7 直接要求 grpc 1.60.0，vertx-grpc 4.5.1 原始要求 1.50.2 被规则抬齐。决定性对照（2026-10-04）：Netty 137 下 36 用例挂 31，压回 4.1.104 全绿。外部检索（不可全信，需矩阵实测校准）：grpc-java 1.74.0 约 2026 年 2 月发布、其构建期依赖 Netty 4.1.118——即 Netty 137 比当前已知 gRPC 官方配套的版本更新，"存在兼容档位"是先验待证命题而非事实。

## Goals / Non-Goals

**Goals:**
- 用一张候选梯度矩阵把"gRPC 哪个版本能与 Netty 137 协同"从猜测变成登记在案的实测结论；
- 有解则落一个版本键并让 docker 档恢复全绿；无解则以矩阵全红证据触发回退预案，两态都算收口。

**Non-Goals:**
- 不改 Netty 事实源（那是治理册主权，本册只提供回退建议权）；
- 不改 jetcd 的封装面与两个消费模块的源码；
- 不引入 shaded 传输（理由见 D4 否决项）。

## Decisions

**D1 改动形态：只动 `gradle.properties` 的 `grpcVersion` 键，不碰任何脚本。**
依据 P11（公共事实源即合同：八大头族托管值单点声明，对账守卫自动核验）与 P13（可验证性：单行 diff 使矩阵结论与落库内容一一对应）。被否决：在消费模块逐个直写版本（绕开托管体系，守卫失明，重复治理册修过的旧坑）。

**D2 候选梯度与选定规则：自 1.61.x 起每取一个代表档（1.61、1.66、1.68、1.71/1.72、1.74），Netty 固定 137 逐档实测；默认选定"最高通过档"，若最高档因 jetcd 二进制兼容失败而低档通过，则选定分界点下最高通过档并在矩阵登记分界。**
依据 P12（结论先于代码：每档先有实测判据再有选择）。选"最高通过"而非"最低通过"的理由：Netty 事实源已领先于 gRPC 官方配套线，取低档会留下"下一次 Netty 升级再撞"的复发缺口，与治理册把版本前推的意图一致；代价（跨度大、行为差异多）由矩阵的逐档记录对冲。被否决：只试最新版一档定生死（无梯度则"全 incompatible"与"个别档不巧"不可区分，回退裁定的证据强度不足）。

**D3 副轴 jetcd 0.8.x：调研阶段查证 jetcd 是否有发布版及其 gRPC 需求；仅当主轴在 jetcd 侧撞到二进制兼容墙（jetcd 0.7.7 编译期绑定 gRPC 内部面被新版移除）时，把 jetcd 升档纳入组合矩阵，组合通过才可落库。**
依据 P10（不预支抽象：jetcd 升档是条件分支不是并列主线，避免一次改动引入两个变量面）。默认组合是 jetcd 0.7.7 不动。

**D4 回退预案两级：矩阵全红 → 结论"Netty 137 在 gRPC 生态当前无兼容档位"，携全量证据移交治理册线，建议二选一（Netty 回 4.1.104，或治理线接受"等 gRPC 官方追平后统一升级"并挂观察位）。次级回退（仅当治理线两案都拒绝）：jetcd 排除 grpc-netty 改用 grpc-netty-shaded（自带内嵌 Netty 彻底解耦）。**
shaded 方案在此明确否决的理由：它绕过 netty-bom 统一，使同一进程出现两套 Netty 类空间，与"八大头族统一托管"的治理哲学正面冲突，且游戏服长连接栈与 etcd 栈各自一份传输实现，排障成本翻倍——只配作最后的逃生舱，不配作正解。

**D5 矩阵判据：主判据 `EtcdNamespaceExplorerIT` 36 用例（本次事故的判据样本，失败签名"流在帧中途收到结束"即计入红），辅判据三件：`tny-game-starter-namnspace` 装配测试、全仓配置阶段对账守卫通过、CI 三通道（unit、docker 档 integration、e2e 中继拓扑）终验。候选档以 `-PgrpcVersion=<档>` 命令行覆写实测，落库才改事实源——每档执行时同时钉 `-PnettyVersion=4.1.137.Final` 防本地缺省漂移。**
依据 P13（每格判据可独立复现）。矩阵文档 `verification/matrix.md` 逐格登记：版本、通过数、首个失败签名摘要、耗时。

## Risks / Trade-offs

- **gRPC 高版本与 jetcd 0.7.7 二进制不兼容**（jetcd 编译期引用 gRPC 内部面，1.61 之后此类面有移除史）→ D3 副轴承接；最坏情形 jetcd 与 gRPC 成对升级，改动面仍在两键之内。
- **矩阵全红**（Netty 137 领先于所有 gRPC 配套线）→ 不是本册失败，是有效结论；D4 一级回退接管，证据包移交。
- **候选梯度采样漏掉分界**（如 1.66 过而 1.68 不过，1.67 未试）→ 分界两侧各加一档细化，仅围绕选定档做一次，不做全量二分（成本受控，矩阵登记细化理由）。
- **本机 OrbStack 与 CI runner 的 Docker 版本差异改变结论**→ 主判据以 CI docker 档终验为准，本地矩阵是筛选器不是终审庭（Migration 已含 CI 步骤）。

## Migration Plan

单键改动，回滚 = 还原该行。顺序：调研定档 → 本地矩阵筛选 → 落库跑本地全量 → 推送以 CI 三通道终验 → 连续三轮绿后销集成测试案卷并收口。任一环节全红走 D4。

## Open Questions

- 无影响本册分解的悬置项。（gRPC 各档的内嵌 Netty 精确值属调研任务 1.1 的产出而非悬置——调研完成即填入矩阵计划。）
