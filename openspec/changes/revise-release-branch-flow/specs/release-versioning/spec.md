# Spec Delta

## ADDED Requirements

### Requirement: 发布容器与标签一经创建不可移动

一个以 `<主>.<次>.<补丁>.release` 形态命名的发布分支连同其附注标签 `v<主>.<次>.<补丁>`
推送到远端之后，两者 SHALL 永久停留在构建该版本发布制品的那个提交上；发布流程中的任何后续
操作（包括把发布分支上的提交合回开发线）都 MUST NOT 改写发布分支的历史、MUST NOT 移动发布
分支的远端头、MUST NOT 移动该标签。合回开发线产生的提交以等价重放的形式只出现在开发线上。

#### Scenario: hotfix 合回之后容器与标签原封不动

- **WHEN** 一次 hotfix 版本发布完成，其发布分支相对切基存在一个或多个修复提交，随后执行合回
- **THEN** 开发线头出现这些修复提交的等价重放；重新核对远端，发布分支头仍指向发布时的制品
  提交，附注标签及其解引用记录同样原封不动，三者彼此一致

#### Scenario: 常规发布切支后无新提交时合回不产生任何移动

- **WHEN** 一次常规发布在切支之后没有产生任何新提交，发布者照常执行合回操作
- **THEN** 合回无事可做并如实报告跳过；发布分支、标签与开发线三者均与合回前完全相同

#### Scenario: 重放合回遇到冲突时全体保持原状

- **WHEN** 把发布分支独有提交重放到开发线头的过程中某个提交发生冲突
- **THEN** 该操作自动中止；发布分支、标签与开发线都停留在执行前的状态，错误信息给出人工完成
  合回所需的等价命令序列

#### Scenario: 事后重新发布同一容器时存证核对仍然成立

- **WHEN** 在发布分支上、合回完成之后的任意时刻，重新执行同一版本的发布构建
- **THEN** 门禁的标签存证校验（远端附注标签解引用对当前构建提交）仍然通过，构建得以重现；
  若制品仓拒绝重复部署，拒绝原因只可能是制品仓的不可变规则，而不是存证核对失败
