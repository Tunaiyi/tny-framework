# 定稿分支模型 git 级沙箱模拟——结果卷宗

被验证的模型（2026-10-05 探索轮定稿）：dev/N.M.x 开发线是特性工厂（并行合法、发
`N.M.x-SNAPSHOT` 字面快照、电梯进 main 后下线）；main 只接收电梯与发布线上合，禁 rebase 禁强推；
release/N.M.x 常驻发布线自 main 梯后切出、只收修复、滚动发 `N.M.K`、附注标签为硬锚永不移动；
修复原型落最老在役受影响线，merge-forward 逐级上合到更新线与 main；cherry-pick 仅为例外通道
（propagated-as 尾注登记、例外随下一版入账）；发版顺序等于版本顺序（更小编号 dev 线未下线则拦截）；
期望号断言（发版号必须恰为该线下一补丁号）；提交前门禁（索引树检索修复标记，防合并冲突解决逐出修复）；
先清账后退役（线上有未入账提交拒绝退役），退役后发布史由标签账本完整存证。

## 运行方式与判定口径

```bash
bash drill/model4-sim/simulate.sh   # 沙箱每次全量重建（/tmp/model4-sim），账本 ledger.txt
```

每个场景一个机器断言；所有断言命令组在 `bash -e` 下执行（任何一步失败则整条记 FAIL，
杜绝"只看末句退出码"的假绿）；脚本退出码 0 当且仅当 FAILS 为 0。**连续两次全量重跑均为
退出码 0、52 项 PASS、零游离 stderr**。终态另有独立复验：对全部十个版本标签逐一重跑
发版流水线断言（附注形态、标签指向的树含正确 dist 产物、树内无冲突标记残留）。

## 一个模型级发现（模拟的增量产出）

常驻发布线的上合（merge-forward 到 main）在"电梯后 main 无人推进"的静默窗口里天然是
fast-forward，**不在 main 的 first-parent 编年史上产生节点**。补丁发布的入账权威因此是标签
账本而非主干合并历史；账本终态逐条打印了每个标签指向的提交以证明这一点。后续规格写作时
不应把"每次发布 main 都有合并节点"当作承诺。

## 第一版模拟的假绿与本次修复史（如实记录）

对抗复核判决对第一版给出"不可用（现状）"，指出四处假绿：其一，`gate_markers` 的
`git grep -c -- "$p" --cached` 参数序错误且报错被吞，门禁恒判拒绝、"拦截"是恒真；其二，
发版链条中 dist 目录缺失的失败被"换行不中断"掩盖，v1.2.0 是无发布提交支撑的空标签；其三，
merge-forward 冲突解决只处理了部分冲突文件，带冲突标记文本的 net.txt 进了 main 树；其四，
"有门禁能拦住"一侧缺少正向对照。第二版全部采纳修复：所有断言命令组改 `bash -e` 语义、
门禁改 `git grep --cached -c` 正确参数序并配正向对照、新增发版流水线断言（标签必须附注、
指向的树含正确 dist 产物、树内无冲突标记）、合并解决显式覆盖全部冲突文件、新增断言可失败性
抽检项、例外通道补"随版入账"、退役补"先清账"门。修复后两次重跑退出码 0。

## 复核判决与覆盖缺口的处置

复核员判决为"不可用（现状），修复后可用"，并列出覆盖缺口两档。本次修复覆盖其中八项：
门禁双对照、断言 set -e 化、发版流水线断言、main 改写守卫、附注标签守卫、切线基座断言、
多线时刻通配重计数、退役前清账门。**明确不覆盖并移交真实实现的**：两条线同刻上合 main 的
竞争（属服务端锁与 CI 串行化，超出客户端级模拟能力）、快照的 Gradle 与制品库全链路
（publishable 本判定逻辑的 git 级复刻）、单双位编号字典序边界（1.9 与 1.10 需数值比较，
真实实现处理）、远端标签强推保护（需在真实 remote 配 pre-receive 钩子）、跳号程序
（模型未设跳号通道；确需跳号属规格空白）。

## 最终判定

本材料可作为"定稿模型在 git 层自洽可行"的**合格证据**进入后续 openspec change 的验证卷宗；
其边界声明如上——它不覆盖服务端并发、Gradle 推导与制品库全链路，这三块由后续变更的
真实发布周期演练（现行三个周期：5.7.x 首发后续补丁、6.0 开线、hotfix）继续取证。
